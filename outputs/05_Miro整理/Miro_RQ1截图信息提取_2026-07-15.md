# Miro RQ1 截图信息提取

整理日期：2026-07-15  
材料来源：用户提供的 Miro 第一部分截图  
对应研究问题：RQ1：对话式心理健康评估在专业实践中需要覆盖哪些关键要素与决策节点？

## 一、整体判断

这组 Miro 截图主要围绕 RQ1 展开，已经形成了较清晰的三段式结构：

1. 评估信息要素：需要收集哪些信息。
2. 判断逻辑：如何根据收集到的信息判断问题类型、严重程度和风险。
3. 处置决策：不同风险等级或问题类型下如何转介、干预或继续评估。

这部分信息可以直接用于补充“访谈需求提炼报告”和后续“智能体设计文档”。它的价值不在于提供新的访谈原文，而在于把专家观点组织成了可操作的系统流程。

## 二、评估信息要素

### 1. 大学生心理问题的主要范围

Miro 中反复出现的大学生常见心理问题包括：

- 抑郁
- 焦虑
- 睡眠障碍
- 学业压力
- 就业压力
- 人际关系困扰
- 恋爱关系困扰
- 原生家庭困扰
- 自我评价问题
- 未来规划与方向感缺失

对智能体设计的启示：

系统不能只围绕“情绪好不好”提问，而应覆盖大学生场景下的学习、生活、人际、家庭、就业和未来规划等具体压力源。

### 2. 初始访谈需要收集的基础信息

截图中提到的基础信息包括：

- 年级、学制、学习状态
- 当前生活状态
- 睡眠与饮食
- 身体情况
- 人际关系
- 自我评价
- 家庭背景
- 未来规划
- 是否存在周围人际支持
- 既往史、家族史、病史
- 地域、文化、宗教等背景信息

对智能体设计的启示：

初始对话应先建立基础画像，再进入具体问题。基础画像字段可以作为报告生成的固定输入项。

### 3. 主诉与问题线索

Miro 中强调评估应以学生或来访者的主诉为主线，而不是机械地按固定题目问完。关键做法包括：

- 先了解来访者“为什么来”
- 顺着主诉自然下探
- 围绕情绪逐步深入
- 贴合叙述线索追问
- 避免脱离语境的生硬提问
- 对不清晰的信息继续追问

对智能体设计的启示：

智能体对话不应设计成纯问卷式流程，而应采用“主诉驱动 + 必要字段补全”的混合模式。

### 4. 风险信息必须前置

截图中多次提到初评需要核查：

- 自伤意念
- 自杀意念
- 自伤或自杀计划
- 自伤或自杀行为
- 既往自伤/自杀史
- 危机程度
- 是否需要紧急处置

对智能体设计的启示：

危机评估应作为 P0 级功能，不能放到后面作为附加模块。系统需要在发现高风险线索时立即切换到安全响应流程。

## 三、判断逻辑

### 1. 判断需要基于完整病史结构

Miro 中出现的判断依据包括：

- 现病史
- 发病时间
- 症状组成
- 情绪表现
- 躯体化表现
- 消极想法
- 生活状态
- 家庭关系
- 学习、人际和生活功能损害
- 症状持续时间、频率和强度

对智能体设计的启示：

系统需要把自然语言对话转成结构化字段，尤其是“持续时间、频率、强度、功能损害、风险线索”这些判断变量。

### 2. 判断过程依赖具体化追问

截图中反复强调“具体化追问”：

- 将主问题落到具体事件
- 追问事件经过
- 追问发生情境
- 追问压力来源
- 追问情绪、想法、行为和身体反应
- 对笼统回答进行核实

对智能体设计的启示：

对话策略中需要设计“追问规则”。当用户只说“最近不好”“压力很大”“睡不着”时，系统不能直接下结论，而要追问具体场景、持续时间和影响程度。

### 3. 诊断标准和量表只能作为辅助

截图中提到 ICD-10、DSM-5、MINI、量表和精神检查等专业工具，但也体现出一个重要边界：

- 咨询场景一般不做医学诊断
- 高校更多做初筛、粗分类、危机判断和转介判断
- 双相、精神病性症状等需要精神科评估确认
- 量表可辅助判断，但不能替代专业访谈

对智能体设计的启示：

系统可以输出“风险提示”“建议进一步评估”“建议转介”，但不应输出确定性医学诊断。

### 4. 严重程度判断的关键变量

截图中涉及的严重程度判断变量包括：

- 症状是否持续超过关键时间阈值，例如抑郁相关症状持续两周以上
- 是否存在明显功能损害
- 是否影响学习、人际和生活
- 是否存在自伤、自杀风险
- 是否存在躁狂、轻躁、妄想等需转诊线索
- 是否存在明显躯体化症状
- 是否适合继续咨询

对智能体设计的启示：

报告中应单独设置“严重程度判断依据”部分，而不是只给一个笼统结论。

## 四、处置决策

### 1. 处置首先看风险等级

截图中提到高校场景常见的分层逻辑：

- 紧急风险
- 非紧急风险
- 长期观察对象
- 需要持续关注的学生
- 需要转介精神科的学生
- 适合继续心理咨询的学生

对智能体设计的启示：

系统需要输出风险分层，而不是只输出心理状态描述。可初步设计为：

- 高风险：立即启动危机响应并建议联系人工/校方/医疗资源。
- 中风险：建议尽快联系心理中心或专业人员进一步评估。
- 低风险：可提供心理教育、日常建议和后续观察。
- 信息不足：继续补充关键评估信息。

### 2. 转介条件

截图中提到需要转介或进一步精神科评估的情况包括：

- 疑似精神病性表达
- 妄想线索
- 躁狂或轻躁线索
- 双相障碍可能
- 严重抑郁
- 高危自伤/自杀风险
- 症状严重到不适合单纯咨询
- 需要药物治疗或住院评估

对智能体设计的启示：

需要建立“转介触发规则库”，将这些高危线索设置为强触发条件。

### 3. 干预和建议需要区分场景

截图中体现了不同场景的处置差异：

- 高校咨询更关注危机分级、是否转医、是否需要长期观察。
- 精神科门诊更关注诊断标准、药物治疗、住院可能。
- 普通心理咨询更关注主诉、关系、情绪和功能恢复。

对智能体设计的启示：

系统应明确自己的使用场景。如果服务对象是高校心理中心，输出应偏向“筛查、分级、转介建议和报告辅助”，而不是医疗诊断。

## 五、可并入报告的结论

Miro 第一部分可以补充进报告中的结论如下：

对话式心理健康评估需要覆盖三个连续环节：首先，系统应收集学生的基本背景、主诉、情绪状态、睡眠饮食、学习生活、人际关系、家庭背景、既往史和风险线索等评估信息；其次，系统需要依据持续时间、频率、强度、功能损害、风险表现和专业标准进行分层判断，并通过具体化追问补足关键信息；最后，系统应根据风险等级和问题类型给出处置建议，包括继续观察、心理咨询、危机响应或精神科转介。对于高校应用场景，系统的定位应是评估辅助和风险筛查工具，而不是诊断工具。

## 六、对现有需求清单的补充建议

根据 Miro 第一部分，建议在已有需求清单中重点补强以下内容：

| 补充需求 | 优先级 | 说明 |
| --- | --- | --- |
| 主诉驱动式对话流程 | P0 | 对话要围绕学生自述展开，同时补齐必要评估字段。 |
| 基础画像采集模块 | P0 | 收集年级、学习生活、睡眠饮食、人际、家庭、支持系统等信息。 |
| 具体化追问规则 | P0 | 对笼统表达进行事件、情境、时间、频率、强度和影响追问。 |
| 危机风险前置筛查 | P0 | 自伤、自杀、计划、行为、既往史必须优先识别。 |
| 严重程度判断字段 | P0 | 记录持续时间、功能损害、风险程度和症状表现。 |
| 转介触发规则库 | P0 | 对精神病性、躁狂/轻躁、双相、高危自杀等线索触发转介。 |
| 高校场景分级处置 | P1 | 区分紧急、非紧急、长期观察和适合咨询等状态。 |
| 报告中的判断依据说明 | P1 | 报告不能只给结论，应说明判断来自哪些信息。 |

## 七、与已有访谈分析的关系

这组 Miro 内容与之前的访谈编码结论一致，尤其强化了以下几点：

- 评估不是一次性问卷，而是访谈式、主诉驱动和动态追问。
- 高校心理健康系统的核心价值是筛查、分级、转介和辅助报告。
- 危机评估必须前置，且要有明确处置路径。
- 医学诊断边界必须谨慎，精神科相关判断应交给专业医生。
- 系统设计应把自然语言内容转成结构化评估字段。

因此，这部分可以作为“需求提炼报告”的项目流程和设计依据补充，也可以作为“智能体设计阶段”的直接输入。
