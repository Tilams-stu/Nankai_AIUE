# Miro 信息提取与智能体设计补充文档

整理日期：2026-07-15  
材料来源：Miro 截图第一部分与第二部分  
适用范围：访谈需求提炼报告、智能体设计说明、日报/周报阶段成果

## 一、Miro 内容的整体价值

Miro 板书内容主要围绕两个研究问题展开：

- RQ1：对话式心理健康评估在专业实践中需要覆盖哪些关键要素与决策节点？
- RQ2：将上述评估过程放入自然语言交互系统时，关键挑战与约束是什么，系统应如何设计以达到安全可控？

从内容结构看，Miro 不是访谈原文材料，而是对访谈观点和专业实践经验的二次整理。它的主要价值在于将专家观点组织成可用于系统设计的框架，尤其适合作为智能体流程、风险控制、报告字段和人工审核机制的设计依据。

## 二、RQ1：专业评估需要覆盖的内容

### 1. 评估信息要素

Miro 中关于评估信息要素的内容主要包括：

- 学生基本背景：年级、学制、学习状态、生活状态等。
- 主诉与来访原因：学生当前最困扰的问题、求助目标和咨询动机。
- 情绪状态：焦虑、抑郁、兴趣下降、情绪低落、情绪波动等。
- 睡眠与饮食：睡眠质量、作息变化、饮食变化等。
- 学业与就业压力：学习压力、考试压力、就业压力、未来规划不确定等。
- 人际与亲密关系：同学关系、朋友关系、恋爱关系、家庭关系等。
- 自我评价与支持系统：自我认知、社会支持、是否有可以求助的人。
- 既往史与家族史：既往心理问题、就诊经历、家族精神心理相关情况。
- 危机风险：自伤、自杀意念、计划、行为、既往尝试和伤人风险。

这些信息说明，智能体不能只围绕“情绪好不好”提问，而应覆盖大学生心理困扰的主要生活场景。基础画像、主诉、功能损害和风险线索都应成为系统报告的固定字段。

### 2. 判断逻辑

Miro 中的判断逻辑强调，专业评估不是简单根据某一句话下结论，而是需要综合多个维度：

- 症状持续时间
- 症状出现频率
- 症状强度
- 对学习、生活、人际和社会功能的影响
- 是否存在自伤、自杀或伤人风险
- 是否存在精神病性症状、躁狂或轻躁线索
- 是否符合 ICD-10、DSM-5、MINI、量表或精神检查中的相关标准
- 用户叙述是否清楚、是否存在矛盾、是否需要继续追问

因此，系统设计中应避免“听到关键词就判断”的方式，而应采用“开放表达 -> 具体化追问 -> 结构化记录 -> 风险分层”的判断流程。

### 3. 具体化追问

Miro 反复强调咨询和评估中的具体化追问，包括：

- 追问事件经过
- 追问发生情境
- 追问持续时间
- 追问频率和强度
- 追问情绪、想法、行为和身体反应
- 追问对学习、人际和生活的影响
- 对笼统表达进行澄清

对智能体而言，这意味着不能只做一次性问答，而要根据用户回答动态补问。例如用户说“最近压力很大”，系统应继续询问压力来源、持续多久、是否影响睡眠学习、是否出现自伤想法等，而不是直接生成结论。

### 4. 处置决策

Miro 中的处置决策主要包括：

- 低风险：继续观察，提供心理教育和自助建议。
- 中风险：建议联系学校心理中心或专业咨询师进一步评估。
- 高风险：启动危机响应，建议立即联系人工支持或医疗资源。
- 疑似精神科问题：建议精神科进一步评估。
- 信息不足：继续补充评估信息，不直接下结论。

这说明智能体报告中应包含“建议处置路径”，而不只是情绪总结。尤其在高校场景下，系统价值更接近“筛查、分级、转介和报告辅助”，而不是诊断。

## 三、RQ2：自然语言系统中的挑战与约束

### 1. 边界与命名

Miro 中明确体现出系统边界问题。当前系统不适合命名为“AI 心理咨询师”或“AI 诊断医生”，更适合定位为：

- 心理状态初筛助手
- 心理健康对话评估助手
- 心理评估信息采集助手
- 高校心理中心辅助筛查工具

系统应在开头明确告知用户：它不能替代心理咨询师、精神科医生或正式诊断，输出结果仅用于初步筛查和辅助参考。

### 2. 误导风险

Miro 中指出，固定选项、多选题和暗示性开场可能诱导用户表达，导致评估结果偏离真实困扰。例如一开始就问“你是不是因为学习压力不好”，可能让用户顺着系统假设回答。

因此，智能体应优先采用开放式开场，例如：

“最近最困扰你的事情是什么？”

然后再根据用户表达补充结构化问题。系统应避免过早假设、过度引导、机械套量表和直接贴诊断标签。

### 3. 用户体验与披露质量

Miro 中提到，用户是否愿意表达与交互形式密切相关。聊天气泡式界面、熟悉的社交软件交互方式、适度共情、允许暂停和跳过，都有助于提升披露质量。

但系统也需要避免“AI 味”过强，例如反复使用模板化安慰、机械总结、假装完全理解或过度拟人化。更适合的方式是有限共情、澄清和具体化追问。

### 4. 危机与转介闭环

Miro 对危机处理提出了明确要求：一旦识别危机，应立即启动清晰流程，而不是只给泛泛建议。危机闭环至少包括：

1. 识别风险信号。
2. 追问风险程度。
3. 判断风险等级。
4. 提供即时安全建议。
5. 提供校内、医疗或社会支持资源。
6. 触发人工复核或转介。
7. 记录风险依据和处置路径。

强制升级条件应包括：

- 自杀计划、工具、时间或既往尝试
- 自伤或伤人风险
- 妄想、幻觉等精神病性线索
- 躁狂或轻躁线索
- 严重抑郁表现
- 信息明显矛盾且伴随高风险信号

### 5. 人机协作与审计

Miro 中还强调，AI 输出不能直接等同于最终判断。系统需要保留判断依据，并允许专业人员审核、修改或驳回。

后台或报告中应保留：

- 用户原始表达摘要
- 被识别的风险线索
- 关键追问结果
- 使用的量表或标准
- 系统判断逻辑
- 风险等级
- 转介建议
- 人工复核状态

这对项目非常重要，因为心理健康评估属于高风险场景，系统必须可解释、可追溯、可人工介入。

## 四、对智能体设计的直接启示

根据 Miro 内容，后续智能体设计可以采用以下流程：

```text
边界声明
-> 开放式主诉收集
-> 基础画像采集
-> 情绪与压力源追问
-> 睡眠、饮食、学习、人际、家庭等功能影响追问
-> 自伤自杀等危机风险前置筛查
-> 具体化追问补足时间、频率、强度和影响
-> 量表或标准辅助判断
-> 风险分层
-> 处置建议
-> 报告生成
-> 人工复核
```

该流程同时吸收了 RQ1 的专业评估框架和 RQ2 的系统安全约束。

## 六、可并入正式报告的段落

Miro 板书内容表明，对话式心理健康评估系统的设计需要同时满足专业性和安全性要求。在专业评估层面，系统应覆盖学生基本背景、主诉、情绪状态、睡眠饮食、学业压力、人际关系、家庭背景、既往史、社会支持和自伤自杀风险等关键要素，并通过具体化追问补足持续时间、频率、强度和功能损害等判断依据。在系统设计层面，AI 不应被定位为心理咨询师或诊断工具，而应作为高校心理健康场景下的初筛和信息采集助手。系统应采用开放式主诉引导与结构化追问相结合的方式，避免暗示性问题和固定选项造成误导。对于自伤、自杀、精神病性症状、躁狂或轻躁等高风险线索，系统必须触发风险分级、人工复核和转介机制，并在报告中保留判断依据，确保结果可解释、可追溯和可审计。

## 七、与已有访谈分析的关系

Miro 内容与前期访谈编码和主题总结基本一致，但它进一步补充了系统设计视角：

- 访谈编码提供原始证据。
- 主题总结提炼专家共识。
- 需求清单转化为系统功能。
- Miro 补充了流程框架、风险边界和人机协作机制。

因此，后续智能体设计可以直接以 Miro 的两个 RQ 框架为主线：RQ1 决定“系统需要评估什么”，RQ2 决定“系统如何安全地评估”。
