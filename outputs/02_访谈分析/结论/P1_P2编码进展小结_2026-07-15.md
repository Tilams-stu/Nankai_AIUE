## 3. P1 初步发现

P1 主要支持 RQ1，即“对话式心理健康评估在专业实践中需要覆盖哪些关键要素与决策节点”。

核心发现：

1. 学校心理咨询与精神科诊断存在明确边界，严重心理疾病或疑似精神病性问题应转介医院。
2. 首次咨询需要采集基本信息、家庭情况、精神病史、既往就医/咨询史、主诉、自伤自杀史。
3. 风险评估需要关注自伤自杀念头、计划、行为和既往历史。
4. 评估应关注症状持续时间、症状程度、生理变化、睡眠食欲变化和社会功能损伤。
5. 文字或纯语音评估存在明显局限，不能替代面对面诊断。
6. 智能体回应不应像“辅导员式说教”，而应更多体现共情、反映和澄清。

## 4. P2 初步发现

P2 同时支持 RQ1 和 RQ2。

RQ1 相关发现：

1. 初步评估应覆盖年级、学习情况、饮食、睡眠、人际交往、自我评价。
2. 需要明确当前困扰、持续时间、社会功能影响、主观痛苦程度。
3. 咨询师会使用具体化技术追问模糊表达和关键线索。
4. 一般心理问题和严重心理问题可从持续时间、功能影响和主观痛苦程度进行初步区分。

RQ2 相关发现：

1. 产品不宜命名为“AI 心理咨询师”，更适合定位为心理陪伴、心理状态评估或心理支持助手。
2. 线上评估无法充分看到环境、动作和表情，信息完整性低于线下面对面评估。
3. SCL-90 等量表自然语言化后，系统需要能识别用户自由表达，而不是只匹配固定选项。
4. 用户表达“我想死”“不想活了”“想伤害自己”等内容时，应触发危机识别和热线/校内资源推送。
5. 危机资源必须使用审核后的白名单，不应从普通知识库召回百度文库、道客巴巴等不受控资源。
6. 开发阶段需要保留对话记录供团队和专家复核，但必须注意隐私授权和后台访问权限。

## 5. 对智能体设计的直接启示

1. 系统定位：心理状态评估与支持工具，而不是心理咨询师或诊断工具。
2. 对话流程：先倾听主诉，再采集结构化信息，再判断风险和分流。
3. 评估字段：基本情况、主诉、持续时间、严重程度、社会功能、睡眠饮食、生理变化、既往史、自伤自杀风险。
4. 危机规则：识别自杀自伤表达后，优先进入危机流程，不继续普通聊天或量表流程。
5. 资源推送：危机场景只推送白名单资源，例如校内心理中心、危机热线、医疗机构或紧急联系人建议。
6. 交互体验：减少机械选项匹配，支持自然语言回答和同义表达映射。
7. 合规边界：报告中使用“初步评估”“风险提示”“建议进一步咨询/就医”，避免诊断结论。
