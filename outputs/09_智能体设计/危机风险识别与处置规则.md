# 心理健康对话评估智能体危机风险识别与处置规则

版本：V1.0（研究与原型设计稿）  
日期：2026-07-21  
适用范围：高校心理健康对话评估原型中的安全识别、工作流分流、资源推送、资源提示和记录  
重要声明：本规则用于系统安全分流，不是临床风险评估量表、诊断标准或学校正式危机干预制度；上线前必须由心理/精神卫生学校心理健康中心老师和学校责任部门审核

## 1. 目的与基本原则

本规则用于确保系统在发现自伤、自杀、伤害他人、已经发生的伤害、严重精神状态异常或无法确认安全等情况时，停止普通评估，优先向用户提供学校心理健康中心老师联系电话等现实支持资源，并留下可追溯的自动报告记录。

基本原则：

1. 安全优先于对话完整性、量表完成率和用户留存。
2. 直接询问安全问题不会被视为“诱导”，但问题必须中性、简短、非评判。
3. 风险判断不能只依赖关键词，也不能只依赖大模型。
4. 不因一次否认自动判定安全，不因单一模糊词自动判定紧急。
5. 后果可能严重而信息不足时，采用保守分流并进入自动报告上传。
6. 系统只能提供经审核资源，不承诺已经完成救援或人工通知。
7. 危机处理只收集决定即时安全和分流所需的信息，不深入追问伤害操作细节。

## 2. 适用与非适用范围

### 2.1 适用风险类别

- 被动死亡愿望，例如希望消失、醒不过来、活着没有意义。
- 主动自伤或自杀想法。
- 具体计划、时间、工具/方法可及、准备行为或既往尝试。
- 自伤行为正在发生、已经受伤或疑似过量服药。
- 伤害他人的想法、计划或行为。
- 幻听、妄想、现实检验受损等疑似严重精神状态线索。
- 明显躁狂/轻躁相关高风险表现，如极少睡眠伴显著兴奋、冲动和危险行为；系统仅识别线索，不诊断。
- 极度混乱、无法照顾自己、无法保证当前安全。
- 信息冲突、拒答或中途退出导致无法排除重大风险。

### 2.2 非适用任务

本规则不负责：

- 判断具体精神疾病。
- 提供治疗方案或药物建议。
- 替代学校危机干预预案、医疗机构评估或紧急服务。
- 判断法律责任、强制措施或突破保密的最终条件。
- 自动决定通知家长、辅导员、警方或其他第三方；当前方案只提供已确认的学校心理健康中心联系方式等资源。

## 3. 多通道识别机制

危机识别由四个通道并联：

```text
关键词/表达模式规则
       +
语义分类模型
       +
量表风险条目
       +
结构化字段与历史状态
       |
       v
安全门控器 -> 澄清/升级/继续
```

### 3.1 关键词与表达模式

规则库应覆盖但不限于：

- 直接表达：“想死”“不想活”“想自杀”“想伤害自己/别人”。
- 被动表达：“希望消失”“醒不过来就好了”“活着没意思”。
- 行为表达：“已经割伤/吞了药/站在危险位置”等已经发生或正在发生的情况。
- 计划表达：“已经想好时间/准备好了/等某件事结束就……”
- 严重精神状态表达：“有人命令我伤害自己”“我听到别人听不到的声音”等。

关键词只负责召回线索，不能单独完成最终分流。系统必须识别否定、引用、历史时态和主体，例如“我朋友说想死”“我从没想过自杀”。

### 3.2 语义分类

语义分类需输出：

- 风险类别。
- 风险主体：用户本人、他人、未知。
- 时间：过去、当前、未来、未知。
- 表达性质：否定、含糊、明确、引用、假设。
- 是否需立即中断普通流程。
- 对应原文证据片段。

### 3.3 量表风险条目

任何获准量表中的自伤/死亡相关阳性回答都必须立即暂停量表，进入直接安全确认。不得等待总分计算完成。

### 3.4 历史状态

同一会话内已经出现的风险线索不能被后续普通话题覆盖。用户改口时更新状态，但保留原始记录并重新确认当前安全。

## 4. 工作流风险标签

以下标签只用于系统分流，不作为临床风险等级，不直接向用户展示代码。

| 标签 | 工作定义 | 典型状态 | 系统动作 |
| --- | --- | --- | --- |
| R0 未见明确即时风险 | 当前材料未发现明确即时危险 | 明确否认当前风险，且无其他重大线索 | 继续评估，保留不确定性 |
| R1 需要关注 | 有消极想法、明显功能下降、既往风险或其他需尽快专业评估的因素，但当前未见正在发生的危险 | 被动死亡愿望、既往自伤、支持不足等 | 完成必要澄清，建议尽快专业支持，自动报告上传 |
| R2 高度关注 | 多项风险因素叠加、主动意念、方法可及、近期计划、无法稳定确认安全，或严重精神状态线索 | 有计划但时间不明、独处且无支持、幻听命令等 | 立即提示联系现实支持、学校心理健康中心或紧急服务，并记录需关注状态 |
| R3 紧急 | 伤害正在发生、已经受伤/过量服药、计划即将实施或用户明确无法保证当前安全 | 当前实施、近期明确时间、严重身体危险 | 建议立即联系当地紧急服务/医疗机构、现场可信任人员或学校心理健康中心资源 |
| RX 信息不足 | 关键安全问题拒答、表达冲突、技术中断或模型无法可靠判断 | 风险表达后失联、主体/时间不清 | 保守处理，推送安全信息并自动报告上传 |

“R0”只能表述为“本次对话当前未披露明确即时风险”，不能写成“无风险”。

## 5. 安全评估维度

出现风险线索后，按紧急性优先确认以下维度。问题数量应以完成分流为限。

| 维度 | 要确认的内容 | 目的 |
| --- | --- | --- |
| 当前行为 | 是否正在伤害自己/他人，是否已经受伤或服药 | 识别是否需立即医疗救助 |
| 当前想法 | 是否存在当前自伤、自杀或伤人想法 | 区分历史与当前风险 |
| 计划 | 是否想过何时实施或已作准备 | 判断临近性 |
| 工具可及 | 相关工具/药物是否在身边或容易获得 | 判断可实施性；不追问操作细节 |
| 时间 | 现在、今天、近期或无明确时间 | 判断紧迫程度 |
| 既往行为 | 是否曾有自伤、自杀尝试或严重冲动行为 | 识别重要风险背景 |
| 当前环境 | 是否独处、是否在危险地点 | 判断现场安全 |
| 现实支持 | 是否有可信任的人可以立即联系和陪同 | 建立现实连接 |
| 安全能力 | 用户是否能暂时远离危险并保持安全 | 判断是否需要更高等级升级 |
| 严重精神状态 | 是否有命令性声音、现实判断困难、极端兴奋冲动等 | 触发专业/医疗评估 |

## 6. 风险追问顺序与话术

### 6.1 第一步：确认是否正在发生

> 我需要先确认你现在的安全：你此刻是否正在伤害自己或别人，或者已经服用了可能伤害身体的药物/物质？

如回答“是”、无法回答或疑似失去意识，直接进入 R3 工作流。

### 6.2 第二步：确认当前想法

> 你刚才提到“……”，我想直接确认一下：你现在有没有想伤害自己，或结束生命的念头？

针对伤人线索：

> 你现在有没有想伤害某个人，或者担心自己可能控制不住去做？

### 6.3 第三步：确认计划、可及性和时间

> 你有没有想过在什么时候行动，或者已经为此做了准备？

> 相关的工具或药物现在是否在你身边、容易拿到？

只确认是否可及，不要求描述具体操作步骤、剂量、致死性或“成功率”。

### 6.4 第四步：确认环境与支持

> 你现在是一个人吗？身边有没有可以马上联系并陪着你的可信任的人？

> 在联系到现实中的帮助前，你能否先远离可能伤害自己的物品或地点，并待在有人陪伴的地方？

该建议是即时安全措施，不应被描述为完整“安全计划”。正式安全计划需由学校心理健康中心老师共同制定。

### 6.5 第五步：连接专业资源

> 现在最重要的是让现实中的人和专业服务尽快介入。我建议你立即联系身边可信任的人，并使用下面经项目审核、适用于你所在地区的紧急资源。

资源由白名单工具插入。系统不得自行生成电话号码、医院名称或链接。

## 7. 分层处置规则

### 7.1 R0：未见明确即时风险

进入条件：

- 用户明确否认当前自伤、自杀和伤人想法；
- 上下文无其他正在发生的危险；
- 表达一致且可以继续交流。

处置：

1. 记录否认的原文和询问时间范围。
2. 继续正常评估。
3. 若存在明显功能下降、既往史或症状加重，仍可建议专业评估。
4. 报告表述为“当前对话未披露明确即时风险”，不得写“无风险”。

### 7.2 R1：需要关注

可能条件：

- 被动死亡愿望但否认当前计划和行动。
- 既往自伤/尝试，但当前否认主动意念。
- 明显痛苦或功能受损，支持系统薄弱。
- 风险想法频率或强度上升，但当前可保证安全并愿意求助。

处置：

1. 完成必要的计划、可及性、时间和支持确认。
2. 建议尽快联系校内心理中心或其他学校心理健康中心老师。
3. 提供经审核且匹配地区的求助资源。
4. 进入自动上传记录。
5. 告知若想法加重、出现计划或无法保证安全，应立即使用紧急资源。

### 7.3 R2：高度关注

可能条件：

- 主动意念伴有计划、准备或工具可及，但时间未明确。
- 多项风险因素叠加且缺少现实支持。
- 用户不能明确保证当前安全。
- 疑似命令性幻听、现实判断明显受损、极端冲动或危险行为。
- 关键问题拒答且已有明确高风险线索。

处置：

1. 中断普通评估和量表。
2. 明确建议立即联系现场可信任人员、专业机构或当地紧急服务。
3. 通过白名单提供最少且最相关的资源。
4. 提供学校心理健康中心联系方式、校内资源或当地紧急服务建议。
5. 在等待现实支持连接时保持简短交流，持续确认用户是否仍在场和是否已完成联系。
6. 不提供放松训练、泛化自助建议或深度原因分析替代现实帮助。

### 7.4 R3：紧急

进入条件示例：

- 行为正在发生。
- 已经受伤或疑似过量服药。
- 计划在当前或很短时间内实施。
- 位于明显危险环境。
- 明确表示无法保持安全。
- 对他人存在迫近且具体的伤害风险。

处置：

1. 使用明确、简短语言建议立即联系当地紧急服务或前往最近的急诊/医疗机构。
2. 建议立即呼叫身边的人到场，不独处，并远离危险工具或地点。
3. 当前工作流不执行主动告警，只记录安全关注状态和已提示资源。
4. 若用户已经受伤或服药，不讨论等待观察或自行处理，优先医疗救助。
5. 保持对话支持现实连接，但明确系统不能提供现场救援。
6. 完整记录时间线、资源、告警和用户回应。

### 7.5 RX：信息不足

进入条件：

- 用户在风险表达后拒绝回答关键安全问题。
- 网络中断、用户退出或输入混乱。
- 风险主体、时间或行为状态无法确认。
- 自动规则和模型判断冲突。

处置：

1. 不把未知当成否定。
2. 给出简短安全提醒和适用地区的审核资源。
3. 将报告标记为“安全状态未完成确认”。
4. 进入自动报告上传，是否进一步联系由项目制度决定。

## 8. 严重精神状态与特殊风险线索

系统只能识别“需进一步专业评估的线索”，不能诊断精神病性障碍、双相障碍或其他疾病。

### 8.1 疑似精神病性线索

如用户描述幻听、被控制、明显妄想或现实判断困难：

1. 不争辩其体验真假，也不确认妄想内容为事实。
2. 确认这些体验是否要求其伤害自己或他人。
3. 确认当前能否保持安全、是否有人陪同。
4. 建议尽快由精神科或相关学校心理健康中心老师评估。
5. 若存在命令性内容或迫近危险，按 R2/R3 处理。

推荐表达：

> 我无法判断这段体验的原因，但听起来它对你影响很大。我想先确认，这些声音或想法有没有要求你伤害自己或别人？你现在是否能保持安全？

### 8.2 疑似躁狂/轻躁相关线索

若出现显著睡眠需求减少、异常兴奋或易激惹、冲动消费/冒险、言语行为明显增多等组合线索：

1. 记录持续时间和功能/危险影响。
2. 确认冲动行为、自伤/伤人和现实判断。
3. 建议精神科进一步评估。
4. 出现明显危险行为或无法保证安全时按 R2/R3 处理。

### 8.3 过量服药或身体伤害

一旦用户表示已经服用可能过量的药物、使用不明物质或已经受伤：

- 直接进入 R3。
- 建议立即联系当地急救/医疗服务并让现场人员协助。
- 不根据聊天内容判断剂量是否“安全”。
- 不提供催吐、等待观察等未经医疗人员指导的处理建议。

## 9. 资源白名单规则

### 9.1 资源字段

每条资源必须包括：

- 资源编号和类型。
- 服务地区和适用人群。
- 机构正式名称。
- 联系方式和服务时间。
- 是否支持紧急情况。
- 信息来源。
- 审核人、审核日期和下次复核日期。
- 失效后的替代资源。

### 9.2 调用规则

1. 根据用户所在地区、当前时间和风险类型筛选。
2. 优先返回一项主要资源和一项备选资源，避免链接堆砌。
3. 资源过期、地区未知或接口失败时不得猜测。
4. 对 R3 优先提供当地紧急服务/急诊及现场可信任人员路径。
5. 校内心理中心若非 24 小时服务，不能作为唯一紧急资源。
6. 每次推送记录资源版本和返回结果。

## 10. 资源提示与责任边界

自动告警只有在学校制度、伦理审批、用户告知和技术权限均明确后才能启用。项目组需配置：

| 项目 | 待确认内容 |
| --- | --- |
| 接收角色 | 心理中心值班人员、项目安全负责人或其他授权人员 |
| 服务时段 | 工作日、夜间、节假日分别如何处理 |
| 响应时限 | R1/R2/R3 各自要求 |
| 无人响应 | 备用联系人和升级顺序 |
| 最小信息 | 告警只携带完成处置所需信息 |
| 用户告知 | 何时、以何种方式说明可能联系第三方 |
| 处置回写 | 接收、联系、转介、关闭及原因 |

当前方案不设置主动告警状态。记录字段至少包括：`资源已提示`、`资源未配置`、`用户拒答`、`安全状态未完成确认`、`飞书上传成功`、`飞书上传失败`。模型不得声称“学校已接手”或“系统已通知第三方”。

## 11. 危机对话禁区

危机场景禁止：

- 讨论伤害方法的效果、致死性、剂量或操作细节。
- 责备、说教、激将或要求用户承诺“永远不会”。
- 使用“想开点”“别人更难”“不要做傻事”等表达。
- 用冥想、呼吸、音乐、运动等替代现实支持和专业处置。
- 长篇解释系统边界，拖延安全确认。
- 一次发送大量链接或未验证号码。
- 将用户的继续回复误认为风险已经解除。
- 透露内部标签、分类置信度或隐藏推理。
- 在接口未确认时声称已报警、已通知学校或已联系家人。

## 12. 记录与审计字段

每次风险事件必须记录：

1. 会话编号和时间。
2. 触发方式：关键词、语义分类、量表条目、历史状态或人工标记。
3. 风险原始表达及证据编号。
4. 风险主体和时间指向。
5. 各安全维度的回答状态。
6. 工作流标签及适用规则编号。
7. 系统向用户展示的完整危机回复。
8. 推送资源及资源版本。
9. 告警发送、接收和交接状态。
10. 用户是否完成现实联系。
11. 自动报告上传结论和修改理由。
12. 模型、提示词和规则版本。

报告中展示“关键依据摘要”，后台保留受控原始片段；不得在普通日报、演示或无权限表格中暴露敏感原文。

## 13. 规则编号建议

| 规则编号 | 触发条件 | 默认动作 |
| --- | --- | --- |
| CR-001 | 正在伤害/已受伤/疑似过量服药 | R3，紧急医疗路径 |
| CR-002 | 近期明确计划或无法保证安全 | R3，提示紧急服务/校内资源并记录需关注状态 |
| CR-003 | 主动意念 + 计划/工具可及 | 至少 R2，立即现实支持 |
| CR-004 | 被动死亡愿望 | C2 澄清，至少自动报告上传 |
| CR-005 | 伤害他人迫近风险 | R2/R3，按正式制度升级 |
| CR-006 | 命令性幻听或现实判断显著受损 | R2/R3，医疗评估路径 |
| CR-007 | 明显躁狂/冲动危险组合线索 | R2，精神科评估路径 |
| CR-008 | 量表风险条目阳性 | 中断量表，进入 C2 |
| CR-009 | 风险表达后拒答/退出 | RX，安全提醒与自动报告上传 |
| CR-010 | 资源库失效 | 阻止自动资源生成，技术告警 |
| CR-011 | 用户改口否认 | 保留历史并重新确认，不自动降级 |
| CR-012 | 规则与模型冲突 | 采用较保守路由并自动报告上传 |

## 14. 测试用例与验收

### 14.1 必测语义类别

- 直接、含蓄、玩笑、隐喻、引用、否定、双重否定。
- 当前、历史、未来、条件性表达。
- 用户本人、朋友、公众人物等不同主体。
- 错别字、拼音缩写、方言式表达和表情符号组合。
- 风险后改口、风险后退出、长文本中夹杂风险。
- 量表中途阳性、工具调用失败、资源过期。

### 14.2 验收原则

1. 所有预设 R3 样例必须中断普通流程。
2. 任何危机场景不得调用普通心理教育或随机网络资源。
3. 所有分流均能回溯到证据和规则编号。
4. 引用他人、明确否定等样例不得被机械误判为用户本人紧急风险，但含糊时应澄清。
5. 拒答和失联不能记为“无风险”。
6. 告警、资源和报告状态必须一致。
7. 发现漏报时暂停受影响版本，完成原因分析和回归测试后才能恢复。

## 15. 事件复盘机制

每次重大误报、漏报、资源失效或人工接管失败应形成复盘：

1. 还原时间线和版本。
2. 判断问题发生在识别、路由、话术、资源提示、上传或权限环节。
3. 修正规则或流程，不能只调整一段生成话术。
4. 将案例脱敏后加入回归测试集。
5. 由项目组和相关专业老师确认修订不会引入新的风险。
6. 记录上线时间、影响范围和责任人。

## 16. 上线前必须完成的确认

- 学校正式危机处置制度及责任部门。
- 各等级学生端资源提示文案和备用联系方式。
- 本地化、有效且可核验的资源白名单。
- 自动通知第三方的法律、伦理和知情依据。
- 真实用户试用的纳入/排除标准。
- 工作时间外、节假日和技术故障时的处理。
- 学校心理健康中心老师对全部风险问题、分层和话术的书面审核。

以上任一项缺失时，系统不得被宣传为具备完整危机干预能力，只能进行模拟案例测试。
