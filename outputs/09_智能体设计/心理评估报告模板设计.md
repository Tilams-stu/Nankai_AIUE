# 心理健康对话评估报告模板设计

版本：V1.0（研究与原型设计稿）  
日期：2026-07-21  
适用对象：学生用户、学校心理中心学校心理健康中心老师及经授权的项目研究人员  
文档目的：规定报告字段、证据来源、生成逻辑、展示差异、自动报告上传和质量校验

## 1. 报告定位

本报告是基于一次自然语言对话形成的“初步心理状态信息整理”，主要用于：

1. 帮助用户回顾本次表达的主要困扰和可行下一步。
2. 帮助学校心理健康中心老师快速了解主诉、状态、功能影响、安全线索和信息缺口。
3. 为后续人工评估、咨询准备或转介提供辅助材料。
4. 记录系统使用的字段、量表、风险规则和人工修改过程。

本报告不用于：

- 确定或排除心理/精神疾病。
- 代替精神检查、面对面访谈、医学检查或正式心理咨询。
- 自动作出药物、住院、强制处置或学籍管理决定。
- 作为对学生进行惩罚、标签化或无关评价的依据。

## 2. 双版本输出策略

系统应生成两个内容范围不同的版本，而不是把专业端报告原样展示给学生。

| 版本 | 主要读者 | 内容重点 | 不应包含 |
| --- | --- | --- | --- |
| 学生端反馈 | 本人 | 困扰总结、已确认的影响、求助建议、学校心理健康中心资源和边界 | 完整后台报告、内部规则编号、模型置信度、隐含推理、飞书记录 |
| 专业版报告草稿 | 授权学校心理健康中心老师 | 完整字段、证据、缺口、风险流程、量表、上传状态 | 无证据诊断、臆测病因、无关个人敏感信息 |

当前方案中，完整报告不直接展示给学生；对话结束后后台静默生成并自动上传飞书多维表格。

## 3. 报告生命周期

```text
会话结束
-> 结构化字段冻结
-> 自动完整性和安全校验
-> 生成报告草稿
-> 自动上传待留档
-> 飞书上传中
-> 上传成功/上传失败/重试中
-> 归档或到期删除
```

报告状态：

- `draft`：系统生成，尚未校验。
- `validation_failed`：字段、证据、措辞或安全状态不合格。
- `pending_review`：自动校验通过，等待后台自动上传。
- `returned`：需补充或修正。
- `uploaded`：飞书上传成功。
- `upload_failed`：飞书上传失败，等待排查或重试。
- `archived`：归档，不再修改。
- `revoked`：因错误或安全原因撤回。

## 4. 字段通用规则

每个报告字段至少包含：

```yaml
field_id: 字段编号
value: 字段内容
information_status: confirmed | uncertain | refused | not_asked | conflicting | not_applicable
source_type: user_explicit | user_confirmed_summary | scale_result | agent_inference | human_review
evidence_ids: [turn_编号]
collected_at: 时间
reviewer_required: true/false
review_note: 人工备注
```

### 4.1 空值规则

- 没有询问：`未询问`。
- 用户不愿回答：`用户选择不回答`。
- 用户不知道：`用户不确定`。
- 用户明确否认：才可写 `用户否认`，并附时间范围和证据。
- 前后不一致：`信息存在不一致，需进一步确认`。

禁止把空白、拒答、退出或模型未识别自动写成“无异常”。

### 4.2 证据规则

1. 事实性字段必须链接至用户原话或用户确认过的总结。
2. 量表结果链接至量表名称、版本、题目回答和计分记录。
3. 风险提示至少包含一条原始证据和适用规则编号。
4. `agent_inference` 只能出现在“待确认”区域，不能直接进入已确认事实。
5. 人工修改必须保留修改前后内容、操作者、时间和理由。

## 5. 专业版报告结构

### T01 报告元数据

| 字段 | 内容 | 要求 |
| --- | --- | --- |
| 报告编号 | 匿名唯一编号 | 必填 |
| 会话编号 | 与对话记录关联 | 必填、受控展示 |
| 对话时间 | 开始、结束、时长 | 必填 |
| 系统版本 | 模型、提示词、规则、资源和量表版本 | 必填 |
| 报告状态 | 草稿/上传中/上传成功/上传失败 | 必填 |
| 上传信息 | 上传时间、工作流状态、报告版本 | 必填 |

### T02 使用范围与局限

固定文本建议：

> 本报告依据用户在本次文本对话中主动提供及确认的信息生成，用于心理状态初步筛查和后台项目记录。受限于信息完整性、文本交流形式和系统能力，本报告不构成心理或精神疾病诊断，也不能替代心理咨询师、精神科医生、面对面评估或紧急服务。报告中的风险标签仅用于系统工作流分流，仅用于后台记录和资源提示逻辑。

### T03 基本信息与当前情境

可包含：

- 年级、专业或当前学习/工作状态。
- 居住与生活状态。
- 与当前困扰相关的校园、家庭、关系或就业情境。

仅显示与本次评估有关且用户同意采集的信息。宗教、性取向、家庭细节等敏感字段非必要不进入报告正文。

### T04 主诉与求助目标

结构：

- `主要困扰`：尽量保留用户自己的表述。
- `本次求助目标`：希望理解、缓解、获得建议或准备求助等。
- `优先议题`：若有多个困扰，标明本次主要讨论哪一个。
- `信息状态`：已确认/待确认。

合格示例：

> 用户表示近一个月同时面临论文和求职压力，最希望先梳理持续失眠及白天难以集中注意的问题。

不合格示例：

> 用户因抗压能力差导致焦虑症。

### T05 问题发展与时间线

字段：

- 起始时间。
- 持续时长。
- 出现频率。
- 主观强度。
- 近期加重/缓解。
- 诱发或相关事件。
- 问题发生前后的变化。

时间无法确认时应保留用户的模糊表述，例如“近期”“开学后”，不能自行推算。

### T06 情绪状态

记录用户明确提到的情绪及其情境、频率和强度，例如低落、焦虑、烦躁、恐惧、空虚、兴趣下降等。

表述方式：

> 用户自述在准备求职材料时经常感到紧张和烦躁；本次对话未确认该情绪在其他情境中的频率。

禁止直接把情绪标签转为疾病名称。

### T07 认知表现

可记录：

- 担忧内容。
- 注意力和决策困难。
- 自我评价变化。
- 消极想法。
- 用户对问题的理解和解释。

禁止把普通想法写成妄想，也不能对用户人格、动机或病因作推断。

### T08 行为与身体状态

可记录：

- 活动水平、回避、冲动和社交变化。
- 睡眠、食欲、体重、精力和躯体不适。
- 与以往状态的变化。

药物信息仅记录名称/是否正在使用等用户自述和来源，不评价是否合理，不生成调整建议。

### T09 功能影响

分别描述：

- 学习/科研/工作。
- 人际与社交。
- 日常生活与自我照顾。
- 兴趣和活动。

每个结论尽量附具体例证。若仅有主观程度词，记录为用户自评，不转化为医学严重程度。

### T10 校园与生活场景因素

按相关性记录：

- 学业、考试、科研、升学和就业。
- 宿舍、同学、亲密关系。
- 家庭关系和近期生活事件。
- 入学适应、休学/退学相关担忧。

该部分用于解释情境，不用于确定病因。

### T11 既往咨询、就医与用药

字段：

- 既往心理咨询经历。
- 既往精神科/其他医疗评估。
- 当前是否接受专业帮助。
- 当前用药自述。
- 既往自伤、自杀或其他危机经历。

用户未提供诊断证明时，不把其自称疾病当作系统确认诊断，可写“用户自述曾被告知/曾接受相关治疗”。

### T12 支持系统与保护性信息

记录：

- 可联系的家人、朋友、辅导员或学校心理健康中心老师。
- 用户愿意采用的求助方式。
- 过去曾有帮助的应对方式。
- 当前是否独处及支持可及性（风险场景）。

“保护性信息”只能作为分流参考，不能抵消明确风险。

### T13 安全风险与处置记录

专业版采用结构化字段：

| 字段 | 内容 |
| --- | --- |
| 安全筛查状态 | 已完成/未完成/用户拒答/中途退出 |
| 风险表达摘要 | 中性摘要，附证据编号 |
| 当前想法 | 否认/被动/主动/不确定 |
| 计划与时间 | 明确/否认/未确认 |
| 工具可及 | 是/否/未确认，不记录无关操作细节 |
| 已发生行为 | 是/否/未确认 |
| 既往行为 | 用户自述及时间 |
| 现实支持 | 是否独处、可联系人、能否保持安全 |
| 严重精神状态线索 | 仅描述线索，不给诊断 |
| 工作流标签 | R0/R1/R2/R3/RX，注明非临床标签 |
| 规则编号 | CR-xxx |
| 已采取动作 | 中断流程、资源推送、告警、人工交接 |
| 自动上传记录 | 上传中/上传成功/上传失败/重试中 |

面对学生展示时不得直接照搬内部标签和详细风险推理。

### T14 量表与结构化工具

如使用量表，记录：

- 名称、版本和授权状态。
- 评估时间范围。
- 完成状态。
- 原始分数和计算工具版本。
- 结果的非诊断性解释。
- 与用户叙述一致/不一致之处。
- 是否触发风险条目。

未完整完成的量表不得给出正式总分解释；自然语言映射未经用户确认时不得直接计分。

### T15 初步归纳与信息缺口

建议分为三部分：

1. `已确认信息`：仅概括有证据的主诉、时间、表现和功能影响。
2. `需进一步确认`：关键缺口、矛盾和未完成评估。
3. `系统局限`：文本信息不足、用户拒答、量表未完成等。

示例：

> 当前对话提示用户近期压力与睡眠变化已经影响白天学习效率；尚未充分确认症状在不同情境中的频率及既往专业评估情况。该归纳仅基于本次文本对话，不构成诊断。

### T16 分流与后续建议

建议分级但不诊断：

- 继续自我观察和获取经审核的心理教育内容。
- 建议预约校内心理中心或专业咨询进一步评估。
- 建议尽快接受精神科/医疗专业评估。
- 建议立即联系当地紧急服务、医疗机构和现场可信任人员。
- 因信息不足，建议人工补充评估。

每项建议都要说明依据和优先级，最多列出三项主要行动。资源必须来自白名单。

### T17 后台自动上传区

字段：

- 上传状态：上传中/上传成功/上传失败/重试中。
- 风险标签调整。
- 信息补充与依据。
- 后续联系或转介安排。
- 不适当系统回应标记。
- 记录负责人、时间和签名/身份标识。

## 6. 学生版反馈模板

```markdown
# 本次状态梳理

## 你主要提到的情况
[使用用户能够理解的语言，概括主要困扰、持续时间和明显影响。]

## 目前已经了解的信息
- [已确认事实 1]
- [已确认事实 2]
- [已确认事实 3]

## 还没有充分确认的部分
- [未询问、用户不确定或需要学校心理健康中心老师进一步了解的内容]

## 建议的下一步
1. [最优先且可执行的建议]
2. [专业求助或复查建议]
3. [需要留意的变化和升级条件]

## 重要说明
这份内容来自本次对话中的信息整理，只用于初步参考，不构成诊断，也不能替代心理咨询师、精神科医生或紧急服务。如果你感到自己或他人可能面临即时危险，请立即联系身边可信任的人，并使用系统提供的、适用于你所在地区的紧急资源。
```

学生版应避免：

- 显示 R0-R3/RX 等内部代码。
- 显示模型置信度或隐藏推理。
- 大段重复用户敏感原话。
- 将“建议专业评估”写成“你患有某病”。
- 将报告包装为正式心理诊断书。

## 9. 措辞规范

### 9.1 推荐措辞

- “用户自述……”
- “本次对话提示……”
- “当前材料中未能确认……”
- “该结果仅作为初步参考……”
- “建议由学校心理健康中心老师进一步评估……”
- “存在需要优先关注的安全线索……”
- “系统工作流将该情况记录为……，并已进入后台上传留档流程。”

### 9.2 禁止措辞

- “确诊为……”
- “排除……”
- “肯定/一定是……”
- “没有任何风险……”
- “人格有问题……”
- “病因就是……”
- “不需要看医生/咨询师……”
- “保证不会恶化……”
- “系统已经报警/联系家属……”（除非接口明确确认且制度允许）

## 10. 自动质量校验

报告生成后执行以下校验：

### 10.1 事实一致性

- 每个事实是否有证据编号。
- 摘要是否改变用户原意。
- 是否把模型推断写成用户事实。
- 时间、频率、主体和否定关系是否一致。

### 10.2 完整性

- 主诉、时间/变化、功能影响和安全筛查是否存在。
- 缺失字段是否正确标记。
- 量表是否记录版本、完成状态和计分来源。
- 风险场景是否记录处置与自动报告上传。

### 10.3 边界与安全

- 是否出现诊断、处方、治疗承诺或不当病因推断。
- 是否把 R0 写成“无风险”。
- 是否包含未审核资源。
- 是否暴露内部推理或不必要敏感信息。
- 告警状态与用户可见表述是否一致。

任一 P0 校验失败时，报告状态设为 `validation_failed`，禁止发布。

| 查看学生版 | 本人按权限 | 可 | 按需 | 不默认 |
| 查看专业版 | 不默认 | 授权个案 | 不默认 | 不默认 |
| 查看原始对话 | 本人按政策 | 授权且必要 | 不默认 | 去标识化故障排查 |
| 修改报告 | 更正本人事实 | 后台记录新版本 | 不直接修改诊断结论 | 不可 |
| 导出 | 按政策 | 授权范围 | 配置权限 | 不可 |
| 查看审计日志 | 不默认 | 个案相关 | 安全管理员 | 技术范围 |

飞书多维表格导出应优先导出结构化摘要、报告状态和去标识化编号。风险原文、详细对话和身份信息不应默认进入同一张普通协作表。

## 12. 报告评审清单

自动上传前确认：

1. 主诉与用户原意一致。
2. 时间、频率、强度和功能影响没有被夸大。
3. 安全筛查和处置记录完整。
4. 量表解释符合批准版本。
5. 没有诊断性、责备性或污名化措辞。
6. 建议与信息和风险程度匹配。
7. 资源有效且适用于用户地区和时间。
8. 信息缺口和不一致已经明确展示。
9. 学生版没有泄露内部推理或不必要敏感内容。
10. 飞书上传字段和权限范围正确。

## 13. 待项目组确认

1. 是否需要同时生成学生端简短反馈和后台完整报告。
2. 专业版报告是否进入飞书多维表格，哪些字段允许导出。
3. 风险记录和对话原文的保存期限。
4. 报告是否需要学校心理健康中心老师电子签名。
5. 用户更正信息后的版本记录机制。
6. 量表分数是否向学生展示，以及采用何种解释文本。
7. 对研究用途的二次使用是否需要单独同意。

在以上问题确认前，本模板仅作为设计和模拟测试标准。
