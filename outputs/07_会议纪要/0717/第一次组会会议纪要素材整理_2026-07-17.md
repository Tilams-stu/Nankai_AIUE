## 四、心理预警项目汇报与讨论

### 4.1 当前完成情况

李锦程汇报了近几天围绕心理预警项目完成的工作：

1. 数据与项目资料调研：
   - 阅读并梳理了既有项目文档、字段说明和相关资料。
   - 对现有数据表进行了字段级理解，将原有图片式字段解释整理为文字版本。
   - 查阅 Kaggle 类似数据集和部分学术资料，用于参考数据处理、建模和心理问题划分思路。

2. 数据表理解与初步筛选：
   - 认为较重要的数据包括学生基本信息、寝室信息、奖助学金/助学金、家长信息、学籍情况、体育成绩、心理测评数据等。
   - 学业成绩覆盖较全面，可作为预测心理情况的重要依据。
   - 新生心理测评数据覆盖较完整，可作为学生入学时期心理状态的基准。
   - 真实就诊/干预记录约 300 条，其中本科生记录约 205 条，是模型验证和标签构建的重要依据。

3. 数据质量判断：
   - 门禁记录时间范围约 7 个月，其中约 3 个月为暑假，代表性有限，且刷门禁行为不能稳定代表睡眠或外出规律，暂不纳入核心建模思路。
   - 锻炼刷卡、跑步、出入校园等数据覆盖率较低，可能存在统计或来源问题，需谨慎使用。
   - 社会实践记录可能存在缺失，奖助记录相对可信，可纳入考虑。
   - 专业培养计划、行政班级等字段可能不是核心变量，过细纳入可能导致参数过多。

4. 建模初步思路：
   - 以学号作为唯一标识，将本科生多张数据表合并为一张大表。
   - 针对不同类型缺失值采用不同补全方式，而不是简单统一填充平均值。
   - 沿用既有项目中的四类心理问题分类，而非直接做十多类细分类。
   - 初步考虑 M0、M1、M1-GR 等模型方案：
     - M0：基础特征输入，输出四类心理问题结果。
     - M1：加入 22 个心理测评指标或其处理后的心理基准分。
     - M1-GR：去除心理测评指标中与标签高度重叠的部分后再建模。
   - 计划使用 softmax 等方式进行多分类预测，并通过正则化降低过拟合风险。

### 4.2 老师与学长反馈

1. 关于真实记录数量：
   - 姚东朋说明，约 300 条记录是全校范围内辅导员掌握的较精准心理问题记录，不是因为未覆盖，而是实际可确认记录本身有限。
   - 这部分数据可作为真实干预/就诊数据使用，但数据量对机器学习训练偏少。

2. 关于训练与验证思路：
   - 可考虑将新生入学测评和老生测评作为训练数据，将 300 条真实记录作为验证或校准依据。
   - 不能单纯追求准确率，因为在心理预警场景中，如果模型全部预测“无问题”，也可能获得很高准确率。
   - 本项目更应关注召回率，即尽可能识别出有风险学生，召回率优先级高于准确率。

3. 关于类别不平衡：
   - 第三类、第四类样本数量少，直接训练会导致模型偏向第一类、第二类。
   - 后续可探索欠采样、类别权重调整等机器学习方法改善类别不平衡。

4. 关于本科生与研究生数据：
   - 本科生和研究生数据字段差异较大，研究生数据缺失更多。
   - 当前可优先在本科生数据上建立模型，后续再考虑研究生数据适配。

5. 关于 API 和字段：
   - 当前接口中的家庭信息较粗，主要包括是否独生子女、国家资助、贫困资助等，缺少父母职业、是否离异等更细字段。
   - 姚东朋表示后续更新 API 时可能加入父母职业、是否离异等家庭信息，但预计需等到下学期。
   - 门禁、奖助勤贷、经济困难、国家资助、绿色通道、成绩等字段需对照现有数据确认是否已纳入。
   - 如果 API 数据有动态更新，可考虑重新爬取，但三周实训不能等待新数据。

### 4.3 平台可视化与界面优化方向

姚东朋提出，心理预警平台应优化管理端和学院端的可视化呈现，形成更类似“驾驶舱”的总体态势视图。

建议优化内容包括：

1. 管理端宏观概览：
   - 总测评人数
   - 当前预警总人数
   - 新生筛查率、老生筛查率
   - 不同学院预警人数分布

2. 预警等级分布：
   - 按 1、2、3、4 级或其他等级展示预警人数和占比。
   - 可使用红、橙、蓝、绿等颜色直观标注不同风险等级。

3. 干预与处置追踪：
   - 展示发生危机人数、已干预人数、已成功干预人数等。
   - 形成处置流程闭环图。
   - 支持由后台或学生详情页状态变更同步更新总览数据。

4. 学院端明细：
   - 展示学生学号、姓名、学院、预警等级、预警原因、辅导员信息等。
   - 支持按学院筛选，例如筛选某学院所有预警学生。

5. 学生个人详情页：
   - 优化原因分析、危机确认、专家复核等功能。
   - 强调可解释性：展示为什么产生该预警，以及各因子或模型输出的依据。

宋泽坤补充，管理端可更偏“科技感”和信息密度；个人详情页应更重视解释性，让教师理解模型判断依据。即使机器学习模型本身具有黑盒特征，也应通过因子得分、风险来源、复核流程等增强科学感和可信度。

## 五、无感知心理测评项目汇报与讨论

### 5.1 当前完成情况

颜浩轩汇报了无感知心理测评项目的阶段性成果。当前重点不是直接开发系统，而是从心理咨询师和精神科医生访谈中提炼需求，明确心理健康对话评估智能体应该评估什么、不能做什么，以及危机场景下如何安全处理。

目前工作围绕两个研究问题展开：

1. 对话式心理健康评估在专业实践中需要覆盖哪些关键要素和决策节点？
2. 将上述评估过程放入自然语言交互系统时，关键挑战和约束是什么？系统如何做到安全可控？

已完成的工作包括：

1. 对既有访谈文档进行编码和整理。
2. 建立包含访谈对象、时间、原文证据、主题、研究问题、关键词和需求转化的编码表。
3. 汇总 11 次访谈材料，形成约 183 条编码记录。
4. 总结出 9 个核心主题。
5. 将访谈分析转化为智能体设计需求、流程和风险合规要求。
6. 结合 Miro 材料，对智能体设计逻辑进行补充。

### 5.2 九个核心主题

颜浩轩从访谈材料中总结出的九个核心主题包括：

1. 自然语言交互的接受度与披露质量
2. 评估信息要素和结构化采集
3. 危机评估和分级处理
4. 评估流程和决策节点
5. 判断标准和量表依据
6. 自然语言交互的挑战与约束
7. 评估与诊断切分
8. 工具定位和边界
9. 人机协作和审计

### 5.3 访谈分析得到的核心结论

1. 心理评估需要覆盖的内容：
   - 基础信息与校园场景
   - 主诉与求助目标
   - 情绪与认知状态
   - 行为和功能损伤
   - 危险评估
   - 诊断标准和量化辅助

2. 危险评估是最高优先级：
   - 必须识别自伤、自杀、精神病性症状或其他危机线索。
   - 一旦触发危机线索，应优先进入安全确认、资源推送和人工转介流程。

3. 需结合大学生校园场景：
   - 宿舍关系
   - 学业和课题压力
   - 入学适应
   - 升学就业
   - 人际关系与情绪困扰

4. 对话方式应避免“填表感”：
   - 不能直接要求用户填写问卷。
   - 应通过自然交流、倾听、情感承接和具体化追问收集信息。
   - 用户体验应减少机器味，避免术语暴露、重复提问和上下文记忆不足。

5. 系统不是心理咨询师或精神科医生：
   - 系统定位应是心理状态评估助手、校园心理知识助手或心理健康筛查工具。
   - 不能代替心理咨询师、精神科医生或紧急服务。
   - 输出应使用“初步评估”“风险提示”“建议进一步评估”等表述，避免诊断式结论。

### 5.4 智能体设计需求

1. 系统定位需求：
   - 面向大学生的心理状态评估和知识辅助工具。
   - 用于自然对话中收集心理评估所需信息，识别风险等级，生成供专业人员参考的初步报告。
   - 不输出疾病诊断结论。

2. 对话流程需求：
   - 系统定义和边界说明
   - 开放式询问主诉
   - 情感承接和初步共情
   - 具体化追问
   - 采集持续时间、频率、强度和功能影响
   - 危机风险筛查
   - 按主诉选择短量表或评估维度
   - 总结确认
   - 生成后台初步报告

3. 核心原则：
   - 先理解，再评估。
   - 先共情，再追问。
   - 危机优先于普通对话。
   - 报告必须可解释、可追溯、可人工复核。

4. 危机响应需求：
   - 设置危机触发线索。
   - 对危机线索进行进一步确认。
   - 必要时中断普通对话流程。
   - 推送资源白名单。
   - 转接人工或建议专业就医。

5. 需求优先级：
   - P0：边界声明、开放式主诉、危机触发规则、危机响应和资源白名单。
   - P1：量表自然语言化、自然语言与量表维度映射、避免重复追问、结构化报告。
   - P2：共情表达、移动端体验、小工具、自我画像等增强功能。

### 5.5 风险与合规要求

需要重点控制以下风险：

1. 伦理风险：
   - 系统被误用为诊断工具。
   - 输出疾病诊断或过度确定性判断。

2. 危机处理风险：
   - 对严重风险识别不足。
   - 危机响应不当，导致用户伤害。

3. 隐私与保密风险：
   - 用户隐私数据泄漏。
   - 访谈、测评、报告等敏感内容未妥善保护。

4. 技术风险：
   - 自然语言理解错误。
   - AI 幻觉或知识库不准确。
   - 错误匹配用户表达与评估维度。

5. 法律风险：
   - 极端事件后的责任归属问题。
   - 用户数据安全与授权边界问题。

结论：除技术实现外，还必须建立伦理审查、数据安全管理和危机处理预案。

     - 方案二：自行编写程序，前端放置一个自然聊天智能体，后端由 PHQ-9、GAD-7 等评估智能体分析聊天记录，并生成报告。

   - 如果自然对话中只能提取出某几个量表维度的有效信息，就只对这些维度得出结论，不强行输出完整量表结果。

4. 关于核心难点：
   - 难点在于如何把自然语言表达与 PHQ-9、GAD-7 等评估标准对应起来。
   - 例如用户说“我好难过”，系统需要判断其频率、强度、持续时间、社会功能损伤和生活影响，而不是仅凭关键词下结论。
   - 该问题可从算法建模和心理学评估两个方向继续探索，也可调研 AI 与心理学领域是否已有类似方案。

5. 关于主题分析方法：
   - 当前项目中使用 ChatGPT 辅助主题分析是可接受的。
   - 如果后续发展为论文，应采用更规范方法：
     - 人工先做一轮主题分析。
     - 大模型再做一轮主题分析。
     - 抽取部分样本进行人工结果与大模型结果对比。
     - 如果重合度达到较高水平，例如约 90%，再说明后续使用大模型进行主题分析具有一定可靠性。

## 六、心理问题比例与模型基准讨论

颜浩轩询问校园真实情况下需要干预的比例。姚东朋说明：

1. 心理问题可大致分为四个等级：
   - 无心理问题
   - 一般心理问题
   - 潜在心理问题
   - 严重心理问题

2. 潜在心理问题：
   - 指困扰持续较久，可能伴随抑郁、焦虑等情况。
   - 大致占比约 10% 至 15%。

3. 严重心理危机：
   - 包括自杀、自伤、精神病发作等严重情况。
   - 全校范围大致占比约 1% 左右。

4. 心理中心咨询数据：
   - 学校有咨询数据，但主要记录频次。
   - 同一人可能咨询多次，因此不能直接等同于人数比例。
   - 一学年咨询频次约六七千次。
   - 该数据敏感，不能开放给项目组。

该比例可作为模型预警基准和风险等级分布参考。

## 七、会议形成的主要决议

1. 两个项目都应基于已有基础继续推进，同时重新梳理方法和流程。
2. 心理预警项目当前不等待新 API 和新字段，先基于现有数据完成算法与方法论沉淀。
3. 心理预警模型评估应以召回率优先，准确率不能作为唯一指标。
4. 心理预警平台后续需优化管理端、学院端和学生详情页，重点提升可视化、可解释性和闭环处置能力。
5. 无感知心理测评项目应先从专家访谈分析转化为智能体需求、提示词和危机响应规则。
6. 无感知测评智能体不能替代心理咨询师或医生，只能作为评估助手、知识助手和筛查工具。
7. 自然语言对话与量表标准的映射是无感知测评项目的关键难点，需要重点探索。
8. 使用 AI 辅助主题分析在当前项目中可行，但若用于论文，应增加人工编码对照和一致性验证。
9. 三周实训的阶段目标是：两个项目都能形成可展示的平台/原型成果，并初步设计后续用户实验访谈大纲。

## 九、可在正式会议纪要中突出的优化建议

1. 心理预警平台优化建议：
   - 建立从数据接入、清洗、特征工程、模型训练、结果解释到平台展示的完整流程。
   - 明确模型评价指标优先级，重点优化召回率和高风险人群识别能力。
   - 增加预警结果解释模块，展示触发因素、特征贡献或风险来源。
   - 建立专家复核和干预闭环，提高平台实际业务可用性。
   - 管理端重视宏观态势，个人端重视可解释性和处置记录。

2. 无感知心理测评优化建议：
   - 将专家访谈结论转化为可执行的智能体提示词、流程图和规则库。
   - 明确系统边界，避免诊断化、医疗化输出。
   - 以自然对话为入口，后端再进行量表维度或风险维度分析。
   - 对危机线索建立强制中断、资源推送和人工转介机制。
   - 对 AI 主题分析增加人工对照，提高方法可靠性。
   - 在用户体验上减少测试感和机器味，增强自然倾诉场景中的信息提取能力。

## 十、正式纪要写作注意事项

1. 不要逐字还原语音转写，应写成正式、简洁、有层次的会议纪要。
2. 涉及学生数据、API、心理咨询数据时，只写原则和管理要求，不写敏感细节。
3. 不要将智能体表述为诊断工具，应统一写作“评估助手”“筛查工具”“辅助参考”。
4. 对未明确的时间、地点、准确平台名称，不要编造，可写“待确认”或略去。
5. 会议纪要应体现两个项目的并行推进：心理预警负责算法和平台优化，无感知测评负责访谈分析和智能体设计。
