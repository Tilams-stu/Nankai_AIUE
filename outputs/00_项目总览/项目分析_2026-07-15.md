# AI + 心理无感知测评项目分析

## 1. 项目一句话定义

这是一个面向学校心理发展中心的 AI + 心理项目，目标是构建一个“基于自然对话的无感知心理测评系统”。

用户与智能体进行正常交流后，系统在后台生成测评报告，最终交付学校心理发展中心使用。

## 2. 项目目标与约束

### 核心业务目标

1. 用自然对话替代传统显式量表填写。
2. 在对话过程中完成心理状态测评与风险识别。
3. 生成面向心理发展中心的测评报告。
4. 后续支持批量导出到飞书多维表格，方便集中查看。

### 关键约束

1. 优先使用学校统一采购的 `coze` 低代码平台，尽量避免新增 API 成本。
2. 自研平台不是主路线，而是补充路线和优化路线。
3. 访谈初步编码、以往同学做过的智能体只能参考，不能直接复用。
4. 所有工作必须留痕：文档归档、日报、周报都要持续产出。
5. 设计必须符合心理学和精神卫生场景的专业边界，尤其要重视危机响应规则。

## 3. 当前可用资源

### 已明确的资源

1. 心理发展中心老师、精神科医生的专家访谈记录。
2. `coze` 平台上已有的 4 个参考智能体，基于 `PHQ-9`、`GAD-7` 等量表转化。
3. 已部署的自研平台基础代码。
4. 共享空间中的文档结构，包括：
   - 访谈文档
   - 伦理审查
   - 会议总结及链接
   - 项目进展
   - 招募计划
   - 质性分析文档




### 主责 1：专家访谈质性分析

要求：

1. 采用 HCI 领域的专业访谈分析方法。
2. 对原始访谈进行编码、归类、提炼需求。
3. 输出可直接支撑智能体设计的需求文档。
4. 结论必须可追溯、可佐证、科学合规。

## 7. 现有代码状态的初步判断

工作区里已有一个自研项目目录：`Mental-LLM_JxFdj`。

从现有文件看，它更像一个已经做出雏形的前端演示 + `coze` 代理接入原型。

### 已看到的代码特征

1. `index.html`
   - 是一个前端单页原型。
   - 包含聊天区、视觉区、数据看板风格模块。
   - 更偏“校园心理陪伴/测评产品展示界面”，不是空白项目。

2. `proxy_server.py`
   - 本地启动 `HTTP` 服务。
   - 代理请求到 `https://coze.nankai.edu.cn/api/proxy/api/v1`。
   - 支持创建会话和流式聊天响应。
   - 会话状态当前保存在内存中，说明更像测试版服务，不是完整生产后端。

3. `test_api.py`
   - 是一个直接测试 `coze` 接口的脚本。
   - 当前文件内存在硬编码凭据，后续如果要继续开发，应尽快改成环境变量或配置文件管理。

### 由此推断出的项目现状

1. 前端界面原型已经存在，后续不是从零设计。
2. `coze` 接入路径已经有人打通过基础链路。
3. 真正缺的是：
   - 科学合规的访谈分析结论
   - 明确的智能体规则设计
   - 稳定的数据存储和账号体系
   - 测评报告的完整管理链路

这与会议纪要中的任务描述是吻合的。

## 8. 你后续写日报时应该围绕什么写

这个项目的日报不能只写“今天看了资料”“今天开了会”，要尽量写成可审计、可累计的工作记录。

建议固定写法如下：

### 1. 今日目标

今天打算完成哪些具体事项。

例如：

1. 完成 2 份专家访谈的开放式编码
2. 初步归纳需求主题
3. 识别高风险对话边界

### 2. 今日完成

要尽量具体到对象、方法、产出。

例如：

1. 分析了 `P1王老师`、`P2王老师` 两份访谈材料
2. 采用开放编码提取出若干初始概念
3. 归纳出若干主题，如测评自然性、风险识别、报告可解释性、隐私与权限
4. 形成了初版需求条目和证据来源对应关系

### 3. 当前产出

要写明你今天留下了什么可交付成果。

例如：

1. 编码表
2. 主题归纳表
3. 需求草案
4. 日报文档

### 4. 问题与风险

建议每天都写。

常见内容包括：

1. 原始访谈材料是否齐全
2. 访谈对象标签是否清楚
3. 旧成果是否只能参考、不能复用导致工作量增加
4. 飞书登录失效影响资料访问
5. 报告字段、数据库结构、权限边界尚未完全明确

### 5. 明日计划

下一步要非常清楚，方便周报汇总。

## 9. 你后续写周报时应该怎么组织

新增的官方周报表要求用“本周实训内容 - 本周成果与进展 - 本周遇到的问题及解决方案 - 下周工作计划”的结构。

### 推荐结构

1. 基本信息：姓名、学号、指导教师、项目名称、周报日期。
2. 本周实训内容：按周一到周五写清楚每天做了什么。
3. 本周成果与进展：写本周形成的文档、分析结论、设计草案或代码进展。
4. 本周遇到的问题及解决方案：写资料缺口、需求不清、合规风险、技术问题及处理方式。
5. 下周工作计划：写具体任务目标、预计完成时间、需要的资源或支持。

### 本项目周报尤其要强调

1. 访谈分析推进到了哪一层
2. 是否已经形成可支撑智能体设计的共识结论
3. 智能体设计是否进入提示词/流程/知识库层面
4. 平台功能优化推进到哪一步
5. 是否已开始测试招募或测试反馈整理

## 10. 当前最值得警惕的风险点

### 1. 资料依赖风险

访谈原始材料、代码资料、参考智能体、共享文档如果交付不完整，会直接卡住你的分析和设计进度。

### 2. 需求定义风险

项目目前目标大方向清楚，但很多细节还没有完全冻结，例如：

1. 最终报告长什么样
2. 报告字段如何定义
3. 风险等级如何判断
4. 对话中什么情况下必须中止并触发危机响应

### 3. 合规风险

这是心理测评场景，任何“过度诊断”“错误安抚”“危机漏判”都会是高风险问题。

### 4. 过程留痕风险

纪要里已经明确强调日报和周报。如果前几天只埋头做分析、不整理过程材料，后面补文档会非常痛苦。

### 5. 技术债风险

现有自研平台原型已经存在，但从代码状态看，后端持久化、配置管理、权限体系都还不像最终态，后续联调可能出现较多返工。

## 11. 你现在最应该立刻推进的事情

按优先级排序：

1. 拿全访谈原始材料。
2. 确认质性分析框架或模板。
3. 开始逐份做编码和需求提炼。
4. 同步建立“证据 - 编码 - 需求 - 设计决策”的追溯链。
5. 每天固定沉淀日报，不等到晚上一次性回忆。
6. 在访谈分析结果成形后，再进入智能体规则设计。
