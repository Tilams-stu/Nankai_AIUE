# 教师远程测试方案

## 1. 方案定位

本方案用于在指导教师或其他测试者没有项目本地运行环境的情况下，通过项目负责人提供的临时在线地址完成体验测试。

这不是“老师自行部署项目”的方案。测试期间，项目负责人负责启动前端、Python 代理和 ngrok；老师只需要使用浏览器访问网址并填写反馈表。

## 2. 测试目标

验证以下原型能力：

- 对话是否自然，是否避免持续收集字段；
- 是否能够保持上下文并应对话题切换；
- 信息充分后是否自动创建或更新后台报告；
- 用户不主动生成报告时是否仍能留下后台记录；
- 结束操作、异常请求和网络波动是否有合理反馈。

本方案不验证心理诊断准确性、临床有效性或正式量表效度。

## 3. 测试角色与前置条件

### 项目负责人负责

- 启动前端、Python 代理和 ngrok；
- 确认服务可以从外网访问；
- 临时提供网址、Basic Auth 用户名和密码；
- 在测试期间保持电脑联网并保持服务运行；
- 保存必要的错误日志、报告更新记录和测试版本信息；
- 测试结束后停止服务并回收临时访问权限。

### 指导教师或测试者负责

- 使用浏览器访问项目负责人提供的网址；
- 按照测试场景完成对话；
- 记录体验中的异常和不自然之处；
- 填写《用户测试反馈表与测试总结报告》中的反馈表部分。

### 测试前由项目负责人提供

| 信息 | 内容 |
|---|---|
| 测试网址 | 由项目负责人临时提供 |
| Basic Auth 用户名 | 由项目负责人临时提供 |
| Basic Auth 密码 | 由项目负责人临时提供 |
| 测试时间窗口 | |
| 当前项目版本 | |
| 问题反馈方式 | |

不得向测试者提供 API Key。测试者也不需要配置 Python、Node.js 或 ngrok。

## 4. 测试流程

1. 项目负责人提前启动服务，并用手机网络或其他外部网络确认网址可访问。
2. 测试者在浏览器打开网址，输入临时 Basic Auth 信息。
3. 测试者阅读测试说明后进行约 5～10 分钟自然对话。
4. 测试者至少完成一次倾诉，并自然切换一次话题。
5. 测试者不需要主动生成报告；如果想结束，可以点击结束按钮。
6. 测试者填写反馈表。
7. 项目负责人核对后台是否生成或更新记录，并记录异常日志。
8. 测试结束后项目负责人停止 ngrok 和本地服务。

## 5. 测试场景

| 编号 | 测试者操作 | 重点观察 |
|---|---|---|
| T01 | 描述近期学习或生活中的一个困扰 | 是否先回应感受，是否自然追问 |
| T02 | 只说“最近有点累”，不主动补充细节 | 是否避免立刻连续索要字段 |
| T03 | 对某个问题回答“我不想说” | 是否尊重拒答并继续交流 |
| T04 | 从学习压力转到人际关系或家庭话题 | 是否能跟随新话题并保持上下文 |
| T05 | 在信息已经比较充分后继续聊天 | 是否后台自动更新报告且不打断交流 |
| T06 | 点击结束按钮 | 是否完成最后一次记录更新 |
| T07 | 输入涉及安全风险的表达 | 是否给出克制、安全的支持性回应 |
| T08 | 刷新页面或模拟一次网络中断 | 是否有明确提示，服务是否仍可恢复 |

如果时间有限，至少完成 T01、T02、T04、T05 和 T06。

## 7. 原型验收标准

- 普通对话能够得到正常回复；
- 不连续重复追问同一个字段；
- 话题切换后能够回应当前话题；
- 信息充分后后台至少完成一次报告创建或更新；
- 用户不点击生成报告也不会完全没有后台记录；
- 点击结束后能够完成最后一次记录更新；
- 异常请求不会导致页面永久空白；
- 前台不显示完整的后台心理报告或内部评估字段。

这些标准用于课程原型验收，不代表医疗或临床结论。

## 8. 无真实用户时的提交方式

如果暂时没有同学参与，提交以下材料：

1. 本测试方案；
2. 一份空白反馈表；
3. 开发者完成的场景验证记录；
4. 运行截图、日志和后台报告更新证据；
5. 说明真实用户测试尚未完成，后续可由教师或其他测试者按本方案执行。

开发者自测结果只能说明功能是否按预期运行，不能写成真实用户满意度或用户研究结论。

## 9. 运行限制与安全注意事项

- ngrok 临时地址只在项目负责人电脑和相关服务运行时有效；
- 免费临时域名可能在重启后变化；
- Basic Auth 用户名和密码只用于本轮测试，不应长期复用；
- 不要在反馈表、截图或答辩材料中公开 API Key；
- 测试结束后应停止 ngrok，并删除或回收临时访问权限；
- 如测试者输入真实的严重心理危机内容，应明确说明本原型不能替代人工危机干预。
