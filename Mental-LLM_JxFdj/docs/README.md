# Docs Layout

Project documents are grouped by purpose:

- `architecture/`: stable project architecture, boundary, and integration design notes.
- `operations/`: runbooks, external validation steps, and platform troubleshooting guides.
- `../archive/history/docs/`: historical refactor notes, presentation notes, and older migration-stage records.

Use `architecture/` first when understanding the current codebase.
Use `operations/` when running live checks or debugging environment issues.
Use `../archive/` only when historical implementation context or preserved test evidence is needed.
