# 无感知测评智能体设计对齐计划

日期：2026-07-28

## 1. 计划目的

本计划用于承接“AI+心理项目无感知测评进展报告”之后的下一阶段工作。当前项目已经完成本地工程化重构、飞书表格链路打通、报告草稿与本地审计基础能力，但仍需要继续对齐 `outputs/09_智能体设计` 中的智能体方案，尤其是对话流程、风险识别、报告模板、数据边界和 NK-GeniOS 配置。

本计划不处理原始 `initial` 项目，后续均以 `Mental-LLM_JxFdj` 当前项目为基础。

## 3. 仍需对齐设计的部分

### P0：下一阶段优先处理

1. **对话流程还没有显式对齐 D0-D12 设计**
   当前代码具备会话、聊天、量表、报告、上传等模块，但还没有把设计文档中的 D0-D12 流程固化为可追踪状态机或结构化阶段字段。后续应明确每一轮处在什么阶段、已收集哪些信息、缺什么信息、下一轮应该追问什么。

2. **报告草稿还不是最终心理评估报告模板**
   当前 `reportDraftService.ts` 生成的是英文后台原型记录，适合联调和审计，但还没有完全对齐设计文档中的中文专业报告结构。后续需要改为非诊断、证据化、可追溯的中文报告模板，并保留字段状态、信息缺口、风险状态、版本信息和上传状态。

3. **风险识别需要从摘要状态升级为证据化规则**
   当前已经有 `SafetyStatus` 和安全摘要，但还需要继续完善风险识别的证据来源、规则编号、否定语境、引用他人、时间范围、退出/拒答、危机升级路径等细节，使其符合“全局安全通道优先于普通对话流程”的设计。

4. **学生端流程需要更贴近“无感知测评”**
   当前项目已有聊天和量表模块，但后续要减少“问卷感”，强化开放式主诉、校园生活语境追问、功能受损信息收集，以及在必要时才引入量表或补充评估。

5. **飞书写入内容需要从四字段入参扩展为稳定记录结构**
   当前工作流入口已经打通四个字段，但 `input` 中承载的内容仍需稳定成可复核报告结构。后续需要明确哪些字段写入飞书、哪些字段脱敏、哪些字段只留本地审计。

### P1：授权通过后联调处理

1. **NK-GeniOS 智能体配置尚未完成真实闭环**
   目前 NK-GeniOS 授权仍在审核阶段，不能宣称线上智能体闭环已经完成。授权通过后需要配置提示词、变量、工具调用、异常处理和 report-to-feishu 工具联调。

2. **本地原型与 NK-GeniOS 的职责边界需要收敛**
   需要明确哪些逻辑由本地前端/代理负责，哪些逻辑由 NK-GeniOS Agent 负责，避免同一规则在两侧重复或冲突。

3. **量表流程需要确定触发、计分和报告写入规则**
   后续需要把 PHQ-9、GAD-7 等量表做成“必要时补充”的流程，明确触发条件、题目呈现、计分、解释边界和报告字段。

4. **资源推荐需要白名单化**
   设计方案强调不能随意给出未经确认的外部资源。后续需要建立校内/热线/官方资源白名单，并让智能体只基于白名单给出支持建议。

### P2：稳定性和汇报材料完善

1. **测试用例需要覆盖边界场景**
   目前已有基础 smoke 和手动用例，后续应补充拒答、重复提问、风险表达、否定风险、引用他人、上传失败、授权失败、字段缺失等场景。

2. **版本追踪需要更明确**
   报告、提示词、风险规则、飞书字段都需要版本号，方便后续说明“这次汇报使用的是哪一版原型和哪一版规则”。

3. **汇报文档需要突出主线**
   当前 Trae 生成的报告内容较完整，但重点不够集中。正式汇报应把第二部分改成“本阶段核心成果”，突出三件事：本地工程化重构落地、飞书表格链路打通、NK-GeniOS 授权审核中并准备继续完善智能体。

## 4. 下一步执行计划

### 阶段 A：先修正汇报材料

- 删除“可视化图文搭配建议”等面向制作者的内容。
- 不保留空白插图占位框和“建议插图位置”。
- 把第二部分改成汇报主线，直接说明本次工作的阶段成果。
- 加入一小节“当前代码与智能体设计方案对照自检”，只保留与后续计划有关的重点。

验收标准：报告能在 3-5 分钟内顺着“做了什么、现在到哪、还差什么、下一步做什么”讲清楚。

### 阶段 B：本地代码继续对齐智能体设计

- 建立 D0-D12 对话阶段状态或等价的流程追踪结构。
- 重构报告草稿为中文、非诊断、证据化模板。
- 完善风险识别、证据记录、风险路径和异常处理。
- 明确学生端可见内容与后台记录内容的边界。

验收标准：一次模拟对话可以产出结构化阶段状态、风险状态、信息缺口和后台报告草稿。

### 阶段 C：NK-GeniOS 授权通过后完成线上闭环

- 在 NK-GeniOS 配置智能体角色、提示词、流程节点和工具调用。
- 对接 report-to-feishu 工具，确认四字段入参和飞书表格写入结果。
- 处理授权失败、写入失败、模型拒答、用户拒答、风险表达等异常分支。

验收标准：完成“学生对话 -> 智能体生成后台报告 -> 飞书记录写入”的真实联调。

### 阶段 D：补充测试与交接材料

- 扩展手动测试案例和 smoke case。
- 给提示词、报告模板、飞书字段、风险规则增加版本号。
- 更新 README 或交接文档，说明如何启动、如何测试、如何查看飞书写入结果。

验收标准：项目可以被他人按文档启动、验证和继续开发。

## 5. 汇报中建议保留的表达

- 当前成果不是“最终临床系统”，而是“本地可交接原型”。
- 本阶段最重要的变化是从“能演示”转向“能继续开发、能联调、能交接”。
- 飞书表格侧已经打通，但完整生产闭环仍等待 NK-GeniOS 授权通过后联调。
- 下一阶段主线只有两条：代码继续对齐智能体设计方案；NK-GeniOS 上继续完善智能体配置。
