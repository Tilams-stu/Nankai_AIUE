## 1. 项目目标与边界

### 1.1 项目目标

将现有 `Mental-LLM_JxFdj` 静态前端原型，逐步整理为一个可持续开发、可测试、可汇报，并能接入 NK-GeniOS Agent 和既有 `report-to-feishu` 工作流的基础工程。

目标闭环为：

```text
学生端自然对话
-> 前端展示与会话状态
-> 本地代理调用 NK-GeniOS Agent
-> Agent 完成主诉理解、结构化追问和安全确认
-> Agent 后台生成非诊断性报告
-> Agent 调用已发布的 report-to-feishu 工作流
-> 飞书多维表格保存后台留档
-> 前端只显示简短结束提示和上传状态
```

### 1.2 明确不做的事情

1. 不把系统实现为心理医生、心理咨询师或诊断系统。
2. 不在学生端展示完整专业报告、内部风险标签或飞书记录。
3. 不由本地前端直接调用飞书接口。
4. 不在未确认知情同意、访问权限、留存周期和脱敏规则前接入真实学生数据。
5. 不编造学校心理健康中心电话、地址或服务时间。
6. 不在没有基线和回滚方式的情况下批量移动或删除旧文件。

### 1.3 原型阶段的验证口径

原型阶段只使用虚构学生信息和测试对话。报告只用于后台留档、项目分析和人工复核材料，不作为临床结论或正式心理评估结果。

### 2.2 本轮审查发现的 P0 风险

1. 当前代码和测试脚本中存在硬编码 API Key，必须先轮换和移除，不能带入重构后的代码。
2. 当前浏览器会把 API Key、学生学号和姓名写入 `localStorage`，不符合最小化数据原则。
3. 当前代理从浏览器请求头接收 Key，后续应改为服务端读取环境变量，浏览器只传业务参数。
4. `report-to-feishu` 是外部已发布工作流，当前只能确认入参，不能把“飞书记录可见”作为本地代码的唯一验收标准。
5. 当前 `End` 节点截图显示引用了插件错误对象，后续必须区分工作流调用失败、写入失败和用户无查看权限三种状态。
6. 当前项目没有可用的 Git 基线，阶段 0 必须先建立可恢复快照或版本基线。

## 3. 技术选型

### 3.1 前端

- 使用 Vite + TypeScript，但不引入 React/Vue 等 UI 框架。
- 保留原有视觉和交互作为迁移基线。
- 使用浏览器原生模块和类型接口，避免继续把逻辑堆在 `index.html`。
- 逐步将外部接口、会话状态、工作流契约从视图中抽离。

### 3.2 后端代理

- 暂时继续使用 Python 标准库 HTTP 服务和 `requests`，不立即改 FastAPI。
- 代理服务从 `server/` 启动，但静态资源根目录必须显式指向项目根目录或构建输出目录，不能依赖当前工作目录。
- API Key 只由服务端环境变量读取，例如 `NANKAI_API_KEY`；不得写入前端源码、HTML 默认值或日志。

### 3.3 测试

- TypeScript 逻辑使用 Vitest 或等价的最小单元测试方案。
- 页面行为使用浏览器冒烟测试；涉及布局或 3D 模型时补充桌面端和移动端检查。
- 测试分为三层：本地离线测试、南开接口测试、飞书外部工作流测试。
- 外部权限不可用时，必须使用模拟响应验证失败分支，不能伪造上传成功。

### 3.4 依赖原则

第一阶段不强行替换 `libs/`。现有本地库先保留并登记来源，之后再逐项迁移到 npm 依赖或确认继续使用。每次替换都必须有页面回归检查。

## 4. 数据流与接口契约

### 4.1 本地对话接口

```text
浏览器
  POST /api/chat
  请求：bot_id、user_id、user_name(可选)、additional_messages
        |
        v
server/proxy_server.py
  服务端注入 NANKAI_API_KEY
  创建或复用 AppConversationID
  请求 NK-GeniOS chat_query
        |
        v
浏览器接收 SSE
  只渲染 answer/content
```

本地前端不再发送 API Key。`user_name` 不是报告必填字段，除非得到明确授权，不应写入飞书或普通日志。

### 4.2 Agent 到工作流的固定契约

既有 `report-to-feishu` Start 节点当前确认有 4 个字符串入参：

```text
input
SEVERITY_LEVEL
Student_ID
time
```

映射必须固定为：

```text
input          <- REPORT_MARKDOWN
SEVERITY_LEVEL <- 非诊断性安全关注状态或上传留档状态
Student_ID     <- STUDENT_ID
time           <- TIME
```

注意事项：

1. `Student_ID` 是工作流入参大小写，不能替换成 `student_id`。
2. `SEVERITY_LEVEL` 不写“重度抑郁”“严重焦虑”等临床化表述。
3. `REPORT_MARKDOWN` 是后台报告正文，不在学生端完整展示。
4. 当前工作流代码节点会把多个参数拼成字段 JSON；在未复制和验证新工作流前，不能假设它已经拆成多列。
5. 用户无权查看原目标表时，只能验证调用链和错误分支；记录内容的最终可见性需要表管理员确认。

### 4.3 外部系统验收分级

| 等级 | 验证内容 | 是否依赖外部权限 |
| --- | --- | --- |
| A | 页面、代理、SSE 解析、字段格式和错误处理 | 否 |
| B | NK-GeniOS Agent 能创建会话并返回对话 | 需要南开接口 Key |
| C | `report-to-feishu` 调用返回成功 | 需要工作流运行权限 |
| D | 飞书多维表格出现可见记录 | 需要目标表查看权限和应用写入权限 |

代码验收不得把 D 级结果替代 A、B、C 级测试。

## 6. 模块职责与边界

### 6.1 视图层

`src/components/` 只负责渲染、用户输入和轻量事件绑定，不负责：

- 诊断或风险判定。
- 拼接飞书字段。
- 保存 API Key。
- 直接调用 NK-GeniOS 接口。
- 展示完整后台报告。

`ReportStatusNotice` 只显示“正在处理、已提交、提交失败、待确认”等状态，不展示报告正文。

### 6.2 服务层

- `chatService`：请求本地 `/api/chat`，解析 SSE，统一超时和错误。
- `sessionService`：管理匿名会话、测试学号和退出/重置状态，不负责诊断。
- 不在本地实现一套与 Agent 重复的报告生成器。

### 6.3 领域层

领域状态必须允许：`unknown`、`not_asked`、`declined`、`pending_review`，不能把缺失信息默认转换为“没有问题”。

领域模型只表达非诊断性状态，例如：

```text
安全状态：未询问 / 未披露明确即时风险 / 需要进一步确认 / 建议现实支持
报告状态：未生成 / 生成中 / 待上传 / 上传失败 / 已提交待确认
```

### 6.4 契约层

`src/contracts/` 定义 TypeScript Interface，作为服务层、视图层和工作流说明之间的唯一字段约束来源。契约必须与 NK-GeniOS 指南中的变量大小写保持一致。

### 6.5 代理层

代理只负责网络转发和会话管理，不负责心理评估、提示词决策或飞书字段拼接。代理日志不得输出 Key、完整对话正文、姓名或学号。

3. 固定工作流大小写映射：`Student_ID` 对应 `STUDENT_ID`。
4. 将 `SEVERITY_LEVEL` 限制为非诊断性安全关注或留档状态。
5. 记录现有发布工作流的权限、输入、输出和错误排查方法。
6. 将上传状态设计为“未触发、处理中、已提交待确认、失败待排查”，不能仅凭前端请求返回就显示成功。
7. 在无法查看目标表时，用模拟工作流响应完成本地测试，并把真实可见性标为外部待确认。

验收：

- 4 个工作流入参及映射无歧义。
- 报告正文不在学生端完整展示。
- 工作流权限失败时前端不会误报成功。
- 能区分调用失败、写入失败和用户无查看权限。

### 阶段 8：分层测试、演示和进度留档

目标：形成可复现、可演示、可汇报的交付状态。

动作：

1. 运行类型检查、Python 语法检查和离线单元测试。
2. 运行页面冒烟测试，覆盖桌面和移动端。
3. 运行模拟 Agent、模拟工作流和权限失败测试。
4. 在有授权时再运行南开接口和发布工作流测试。
5. 保存测试结果、截图和未解决问题到 `testing/`。
6. 按生命周期模板写入 `progress/YYYY-MM-DD_log.md`。
7. 更新 `docs/presentation_notes.md`，区分已完成、进行中和待外部确认事项。

验收：

- 至少 8 个手工场景有输入、预期行为和通过标准。
- 离线测试不依赖真实密钥。
- 失败分支和安全边界均有测试证据。
- 汇报材料不把原型验证说成临床验证或正式部署。

## 14. 风险与阻断条件

以下情况出现时，必须暂停进入相关阶段并报告，而不是假设成功：

1. 无法确认已暴露 Key 是否已轮换。
2. 无法恢复重构前原型。
3. 真实学生数据的知情同意、访问权限或留存周期未确认。
4. Agent 的工作流入参发生变化但没有新的截图或契约依据。
5. 飞书应用没有写入权限或用户没有目标表查看权限。
6. 学校心理健康中心的真实支持资源未确认。
7. 迁移后页面、模型或流式对话无法通过基线测试。
