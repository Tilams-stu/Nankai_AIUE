# AIUE 项目结构治理计划 / AIUE Project Structure Governance Plan

## 结论

AIUE 按混合项目处理，先建立根目录入口、所有权清单和证据目录，再分阶段迁移设计资料、研究分析、交付物和历史原型。第一阶段不改动 `Mental-LLM_JxFdj`、`md`、`outputs` 和 `initial` 的主体路径。

## 当前问题

- 根目录没有项目级 README，也没有统一的结构清单。
- 根目录存在 UI 验证截图和 PPT 评审缓存，职责不清晰。
- `md/` 是项目级文档中心，但 `02-design`、`03-meetings`、`05-reporting` 为空，部分对应资料仍在 `outputs/`。
- `outputs/` 同时包含工作材料、分析数据、过程记录和最终交付物。
- 应用内同时存在 `tests/`、`testing/` 和 `__tests__/`，需要区分可执行测试和验证记录。
- 根目录 `.git` 当前不是可用 Git 仓库，版本边界仍需后续决定。

## 暂不迁移

- `Mental-LLM_JxFdj/`：维护中的应用和运行时边界。
- `md/`：现有项目文档入口，历史链接较多。
- `outputs/`：已被多个历史记录引用，需先建立文件级映射。
- `initial/` 和 `initial.zip`：前置原型和素材，需先更新历史引用。
- `archive/`、`tmp/`：已有历史和渲染缓存，先标记职责，不做清理。

## 第二阶段候选

1. 把 `outputs/09_智能体设计` 中仍在维护的设计源文件迁入 `md/02-design/`，把正式导出物留在交付目录。
2. 把 `outputs/02_访谈分析` 中的编码表和分析过程与最终结论分开。
3. 检查并处理 `Mental-LLM_JxFdj/testing/` 空目录，以及 `tests/` 和 `__tests__/` 的职责边界。
4. 完成 `initial/`、`initial.zip` 到归档目录的迁移，并更新历史文档中的路径说明。
5. 决定 AIUE 是否建立根级 Git 仓库，或只把 `Mental-LLM_JxFdj` 作为代码边界。

- 使用 `govern-project-structure` 的扫描脚本和结构校验器。
