## 1. 产品视角

本路线图只讨论学生能直接感知到的完整体验。目标不是增加更多页面，而是让“校园心理驿站”从一个聊天原型变成一个可理解、可持续使用的学生支持工具。

核心用户旅程：

```text
获得入口
-> 了解边界并开始
-> 自然聊天
-> 按需补充测评
-> 查看个人梳理状态
-> 使用白噪音/短暂休息
-> 随时继续、纠正、暂停或结束
```

## 2. 交付形态：先网站，后可安装

### 推荐结论

第一阶段采用校园网站 + PWA（可选“添加到主屏幕”），不优先开发原生 App。

### 原因

- 学生通过校园链接、二维码或统一身份入口即可使用，不需要下载、安装或等待应用商店审核。
- 对话策略、安全文案和隐私规则可以集中更新，避免学生停留在旧版本。
- PWA 可提供“像应用一样”的图标、全屏启动和白噪音资源缓存；聊天和报告仍需要网络。
- 只有在明确需要离线功能、系统级通知、设备深度能力或校方统一分发时，再评估原生 App/桌面端。

### 待实现能力

1. 校园入口页、短链接和二维码落地页。
2. 首次进入时的简短用途、隐私、非诊断边界和用户控制说明。
3. PWA manifest、安装提示和白噪音静态资源缓存策略。
4. 无网络、服务不可用、恢复失败时的可理解页面，不让学生误以为对话已保存。

## 3. 首页：聊天不是唯一入口，但应是默认入口

### 用户目标

学生进入后应立即知道“我可以聊什么”“这不是诊断”“我可以随时跳过或结束”，而不是面对空白输入框或一套隐形问卷。

### 首屏应具备的体验

1. 一个简短的自然开场，支持学生自由表达。
2. 三个轻量入口：`聊聊最近的事`、`做一次补充梳理`、`先休息一下`。
3. 聊天中只在必要时引导补充测评或白噪音，不用弹窗强迫跳转。
4. 用户可继续上次会话、开始新会话、纠正已有总结、暂停或结束。
5. 网络、保存和后台记录状态使用清楚但不惊扰的文案。

### 对话体验原则

- 开放表达优先于追问。
- “回应 + 主题承接 + 可选开放邀请”优先于字段式问题。
- 当信息足够或用户不愿继续时，提供总结和退出空间。
- 所有跨页推荐都是可选的：例如“如果你愿意，也可以做一个简短的补充梳理”或“想先安静一会儿，也可以去白噪音空间”。

## 4. 第二页：补充测评应是可选、可解释、可返回的

### 定位

“补充测评”不是聊天失败后的补考，也不是默认必经问卷。它是学生主动选择或本地策略建议的一种补充信息来源。

### 功能要求

1. 展示每个量表的用途、题量、预计耗时、数据如何使用和“非诊断”说明。
2. 只接入学校审核通过、适用于目标学生群体且计分规则明确的量表。
3. 每个量表必须有版本号、题目来源、计分规则、适用范围和结果解释边界。
4. 学生可以跳过、退出和稍后继续；未完成不能被写成负面结论。
5. 结果以“补充参考”方式呈现，不替代对话、专业评估或安全分流。
6. 高风险项目或异常结果进入既有安全流程，而不是仅显示分数。
7. 聊天、量表和报告共用同一份本地状态与证据来源，避免同一信息重复录入。

### 建议的学生侧结果表达

- “本次补充梳理提示你最近的压力/焦虑相关体验值得继续关注。”
- “结果仅供初步参考，不构成诊断；你可以结合聊天中的内容继续梳理或寻求现实支持。”
- 不展示未经验证的“心理健康总分”或疾病标签。

## 5. 第三页：从静态状态页变成“个人梳理中心”

### 定位

状态页不应展示内部字段、风险标签或完整报告，而应让学生知道：系统已梳理到什么、接下来可以做什么、自己仍拥有控制权。

### 可展示内容

1. **本次状态**：正在梳理 / 已完成初步梳理 / 已生成记录待确认 / 需要继续支持。
2. **非敏感主题摘要**：例如“近期困扰”“日常状态”“补充梳理”，不展示内部证据和安全标签。
3. **学生可操作项**：继续补充、纠正总结、开始补充测评、前往白噪音、暂停、重新开始、了解数据处理。
4. **补充测评记录**：完成状态、日期、用户可见的非诊断性说明。
5. **资源入口**：仅在适当安全情形展示现实支持和紧急帮助说明。
6. **数据控制**：会话是否保存、保留到何时、如何申请删除或退出。

### 禁止展示内容

- `R0/R1/R2/R3/RX` 等内部标签。
- “未询问字段”清单、隐藏上下文、完整后台报告、payload、工具状态。
- 伪临床诊断、人格标签或未经验证的综合分数。

## 6. 第四页：白噪音空间要成为可用工具，而非装饰页

### 定位

白噪音空间是一个可选的短暂休息工具，不是治疗功能，也不应暗示能处理危机。

### 功能要求

1. 确认当前音频资源、播放、暂停、音量、计时、切换和移动端后台播放是否真实可用。
2. 提供少量清晰场景：专注、放松、入睡前、短暂呼吸休息；不夸大效果。
3. 支持组合声音、音量平衡、15/30/45 分钟计时和最近使用设置。
4. 聊天中只能以可选方式推荐，例如学生提到睡眠或需要安静时；不能用白噪音替代安全支持。
5. 白噪音结束后提供“回到聊天”“继续休息”的无压力选择。
6. PWA 中缓存公开音频资源；明确资源版权、体积和离线范围。

## 7. 跨页面连续体验

### 需要统一的状态

1. 会话身份、同意状态、当前聊天摘要、补充测评状态、白噪音偏好和学生可见状态。
2. 页面切换不能丢失当前输入、正在播放的声音或未完成的补充测评。
3. 聊天中推荐进入第二、四页时，返回聊天后仍保持原会话上下文。
4. “重新开始”必须清晰区分：仅清空学生端展示、开始新会话、还是申请删除历史记录。

## 8. 无障碍、移动端与可信感

### 必须考虑

1. 手机优先：输入区域、底部导航、弹窗、长文本、键盘遮挡和弱网状态。
2. 无障碍：足够对比度、字号调节、键盘操作、焦点状态、屏幕阅读器标签、非声音提示。
3. 情绪敏感场景：避免强闪烁、倒计时压迫、夸张动效、强制登录和强制填写。
4. 可信信息：用途、边界、数据处理、现实支持和退出方式随时可找到。
5. 真实校园品牌、支持资源和内容责任人，避免空泛的“心理陪伴”宣传。

## 9. 推荐实施顺序

1. 先完成发布后真实对话和工作流验收。
2. 交付 PWA/校园入口、首页开场和动态状态页，形成最小完整学生旅程。
3. 接入一项经过学校审核的补充测评，先建立量表注册、计分和结果边界，再扩展更多量表。
4. 完成白噪音页面真实播放、计时和移动端体验，随后才做聊天联动推荐。
5. 最后做跨页连续体验、可访问性优化和更丰富的个性化设置。

## 10. 验收标准

一名新学生应能在不阅读技术说明的情况下：

1. 通过链接或二维码打开并理解用途与边界。
2. 自然开始聊天，感到可以自由表达而非完成问卷。
3. 自主选择或理解何时需要补充测评。
4. 在状态页看懂“我目前能做什么”，而非看到内部系统数据。
5. 使用白噪音进行短暂休息，并能无缝回到聊天。
6. 随时暂停、纠正、结束或了解数据处理方式。
