## 1. 使用说明

本文件记录无法单靠代码和现有台账确定的产品、数据、现实支持和平台决策。2026-07-31 已根据用户逐项回复更新：已确定的项目标记为“已确认”，其余保留为外部事实、后置能力或待理解的技术选项。

每项包含：

- **需要确认的问题**：最终必须明确的选择。
- **建议默认值**：从安全、可解释和课程原型边界出发的建议。
- **未确认时行为**：在没有正式答案前，系统必须采用的保守行为。
- **影响范围**：该决定会改变哪些功能。

技术上已经能够确定的事项，例如“上下文按时间排序”“第三方内容不写入本人报告”，不在此重复要求确认。

## 2. A 类：项目定位与“无感知”的含义

### DEC-001 无感知是否包含后台分析和记录（已确认）

- **需要确认的问题**：项目中的“无感知”是仅指“不使用问卷式追问”，还是也希望用户不明确知道后台分析和生成记录？
- **确认结论**：无感知包含后台分析、报告生成和自动记录；用户不需要点击生成报告或主动说明要生成报告。
- **实现规则**：首次有效本人困扰自动 create，后续有效证据变化自动 update；结束按钮只触发最后一次 update。
- **边界说明**：无感不改变“被直接问到数据去向时必须如实回答”的事实；系统不得就访问范围、留存期限或保密程度作未经确认的承诺。
- **影响范围**：开场说明、同意状态、报告触发、隐私回答。
- **待填写选择**：

### DEC-002 用户说“先别分析”时是否停止后台提取（已确认）

- **需要确认的问题**：用户明确说“先别分析我”后，是只停止追问，还是连后台测评字段提取也暂停？
- **确认结论**：不暂停后台测评提取；核心要求是停止字段驱动、问卷式追问。
- **实现规则**：进入 `free_chat`，移除 `missingFields`、`targetField`、`nextQuestionPriority`；后台证据提取和报告 update 继续运行。
- **影响范围**：InteractionState、AssessmentState、报告内容。
- **待填写选择**：

### DEC-003 “随便聊聊”和“不要分析”是否视为同一种边界（已确认）

- **需要确认的问题**：两种表达是否都暂停后台评估？
- **确认结论**：两者都表示用户希望交流更自然，不希望系统持续提问；后台测评仍继续。
- **实现规则**：允许具体承接、表达 Agent 的审慎看法和围绕当前话题的开放式追问；禁止为了时长、情绪、功能影响等字段切题或连续追问。
- **影响范围**：边界分类和恢复条件。
- **待填写选择**：

### DEC-004 信息充分后系统能否主动结束（已确认）

- **需要确认的问题**：信息足够时系统应主动结束，还是只总结并等待用户决定？
- **确认结论**：信息充分后不主动结束；必须自动创建或更新报告，用户仍可继续交流。
- **实现规则**：`assessmentSufficient` 和 `reportDirty` 都触发后台 update，`closingRequested` 只负责最后一次强制 update。
- **影响范围**：BUG-007、BUG-010、收尾状态机。

## 3. B 类：同意、身份和上传控制

### DEC-005 是否拆分“使用对话”“允许分析”“允许上传”三种同意（已确认）

- **需要确认的问题**：用户是否可以聊天但不允许生成或上传后台记录？
- **确认结论**：当前测评原型不向用户提供暂停后台测评或拒绝上传的控制；聊天、分析和自动报告属于同一产品流程。
- **实现规则**：删除以 `reportUpload=granted` 作为自动 update 前提的设计；保留内部状态只用于审计，不形成学生端控制。
- **影响范围**：登录、开场、DataPermission、报告和工作流。
- **待填写选择**：

### DEC-006 上传同意应在何时获取（已确认）

- **需要确认的问题**：进入系统时一次性获取，还是在结束生成记录前再次确认？
- **确认结论**：不要求用户在结束前确认上传，也不要求点击生成报告；后台按测评状态自动 create/update。
- **实现规则**：保留结束按钮，但其语义是结束对话并进行最后一次报告 update，不是授权按钮。
- **影响范围**：结束按钮、状态 UI、BUG-020/026。
- **待填写选择**：

### DEC-007 是否必须使用真实姓名和学号（已确认）

- **需要确认的问题**：普通使用和测试是否都要求真实姓名、学号？能否允许匿名测试编号？
- **确认结论**：报告默认包含学号，不采用匿名模式；姓名不是当前报告必需字段。
- **实现规则**：`studentIdRequired=true`；报告和飞书继续以学号、会话 ID 和时间完成同会话 update。
- **影响范围**：登录页、报告、飞书字段、数据边界。
- **待填写选择**：

### DEC-008 用户拒绝上传后是否允许生成仅本地临时摘要（不适用于当前产品）

- **需要确认的问题**：拒绝上传时，是否仍可在当前内存中生成用于对话总结的临时摘要？
- **确认结论**：当前产品不提供拒绝上传分支，后台报告自动生成和 update。
- **实现规则**：移除 `not_uploaded` 作为正常学生操作终态；该状态仅保留给技术失败、会话缺少任何可报告本人信息等异常情况。

## 6. E 类：报告内容与学生可见范围

### DEC-019 学生是否能看到本次记录摘要（已确认）

- **需要确认的问题**：学生能否查看“系统记录了哪些事实”，以及查看到什么粒度？
- **确认结论**：后台报告默认只由心理健康老师查看，学生端不主动展示报告或记录摘要。
- **实现规则**：学生端只维持自然对话；用户主动询问记录时按已确认事实回答，不展示内部 payload、风险标签或完整报告。

### DEC-020 报告是否必须包含未涉及的所有字段（待结合既有讨论确定）

- **需要确认的问题**：后台报告是固定完整模板，还是只显示已涉及字段并单列关键缺口？
- **当前方向**：报告字段问题的优先级是“事实正确、不要混入问候和结束语、不要漏掉睡眠与功能影响”，而不是要求 Agent 为填满模板反复追问。
- **暂定实现**：保留核心模板，未知字段显示“本次对话未涉及/信息有限”，但不将缺口反推为对话问题。

### DEC-021 报告中的“下一步建议”由什么规则产生（部分确认）

- **确认结论**：建议应尽量依据科学标准；没有足够标准或证据时不强行填写。
- **实现规则**：新增 `RecommendationPolicy` 只在具有明确证据规则时输出建议；其余报告写“当前信息不足以形成进一步建议”，不由 Agent 自由编造。

## 7. F 类：工作流与平台能力

### DEC-023 是否可以由本地代理直接调用发布工作流（已确认）

- **需要确认的问题**：NK-GeniOS 是否提供安全、可授权的工作流 API，使本地代理无需通过学生侧 Agent 调用工具？
- **确认结论**：本地不能直接调用工作流，必须由 Agent 调用。
- **实现规则**：保留 `agent_internal`，每次自动 update 通过隐藏 Agent 工具 payload 请求 `report-to-feishu-yhx`。
- **影响范围**：BUG-004、011、026、WorkflowDeliveryService。
- **需要向谁核实**：NK-GeniOS 平台管理员或工作流配置人员。
- **待填写结论**：

### DEC-024 Agent 内部工具调用结果能否被本地可靠获取（当前限制已确认）

- **需要确认的问题**：平台是否返回工具调用成功、workflow run ID、错误原因或最终输出？
- **确认结论**：当前只能由人工查看平台后台日志或审计文件，浏览器与本地运行时拿不到可靠最终回执。
- **实现规则**：自动 update 后只能标记 `submitted_unconfirmed`；不增加伪造成功提示。此限制不阻止自动 update，但会保留为报告链路的已知局限。
- **影响范围**：DeliveryState、状态文案和重试。
- **需要向谁核实**：NK-GeniOS 平台管理员。
- **待填写结论**：

### DEC-025 是否允许增加独立结构化抽取调用（技术选项，暂缓）

- **含义说明**：除“学生聊天 Agent”外，再增加一次后台不可见模型调用，只让它返回结构化 JSON，例如“这句话是否包含睡眠、功能影响、主体是谁”。它不直接回复学生。
- **作用**：提高报告字段提取准确度，不负责决定如何聊天。
- **当前处理**：暂不依赖第二次模型调用；先用分句、本地规则、主体识别和证据关系修复 BUG-001/002/006。后续如果本地提取仍明显漏项，再确认平台、成本和延迟是否允许加入。
- **影响范围**：AssessmentEvidenceExtractionService、运行成本、延迟。
- **待填写选择**：

### DEC-026 是否能配置独立工具提交 Agent 或请求类型（技术选项，当前不要求）

- **含义说明**：仍然通过 Agent 调工作流，但把“聊天回复”和“提交报告”的平台请求分开。后者只带四字段 payload，不让模型同时聊天和决定是否调工具。
- **当前处理**：不要求新建 Agent；继续使用现有 Agent 的隐藏工具请求。若平台未来支持独立请求类型，可再将工具调用从聊天链路中拆出。
- **影响范围**：Agent 配置、代理、工作流可靠性。
- **需要向谁核实**：NK-GeniOS 平台管理员。

## 9. 当前已确定的实现约束

1. 后台无感测评和报告自动 create/update，不要求用户点生成报告。
2. 信息充分时 update 报告但不结束对话；结束按钮只触发最后一次 update。
3. “先别分析/随便聊聊”禁止字段驱动追问，但继续后台测评和自然交流。
4. 用户不控制后台测评；报告默认绑定学号，不采用匿名模式。
5. 报告目标读者为心理健康老师，学生端不主动展示完整报告。
6. 同一会话中的新证据和修正自动 update 原飞书记录。
7. 本地必须经 Agent 调用 `report-to-feishu-yhx`，不能直接调用工作流。
8. 本地拿不到可靠工作流回执时，仅标记 `submitted_unconfirmed`。
9. 高风险没有人工复核闭环；安全拒答必须写为信息不确定。
10. 第三方或虚构内容不能误写进当前用户报告。

## 10. 未确认时的最小真实性规则

1. 不承诺绝对保密、精确 ACL 或固定保存期限。
2. 不声称系统会自动通知老师、家长或心理中心。
3. 不把安全拒答或未询问解释为无风险。
4. 不把身体症状直接归因为心理问题。
5. 不把“本地 payload 已准备”显示为“飞书写入成功”。
6. 不确认的评估字段保持未知，不通过连续字段追问强行补齐。
