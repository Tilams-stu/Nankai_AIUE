## 1. 产品目标

将项目从“可运行的对话原型”推进为可验证、可审计、对学生自然且对管理者可解释的非诊断性对话测评应用。

前台目标：帮助学生表达、梳理近况并获得下一步建议，而不是完成一张隐藏问卷。  
后台目标：以可追溯证据形成初步评估记录、分流状态和报告，不把模型自然语言当作报告事实来源。

## 3. P0：发布后真实闭环验收

### 目标

先验证刚完成的策略不是“本地测试通过但平台实际无效”。在未完成这一项前，不扩大 UI 或量表功能。

### 验收场景

1. 核心信息足够但没有提到“报告”：Agent 总结，用户回复“好的”，进入收束。
2. 用户表达很少：连续低信息后总结，用户回复“好的”，仍生成带信息缺口的本地报告。
3. 用户明确结束：`今天先这样` 不会继续追问。
4. 安全确认：仅在策略要求时出现一次；明确否认、拒答、模糊回答分别进入正确状态。
5. 报告闭环：Agent 工具输入四字段与本地 audit 的 payload hash 一致，Feishu 出现一行记录。

## 4. P1：将策略从“提示词建议”升级为本地硬控制

### 问题

当前 `responseMode` 已由本地确定，但 Agent 看到的是拼接进 Query 的上下文，模型仍可能忽略 `summarize`、`close` 或继续追问。

### 改造方向

1. 为 `summarize`、`close`、`safety_check` 增加本地受控回复模板或受控生成路径；这些模式不再完全依赖普通 Agent 自由回复。
2. 对 Agent 回复做结构检查：`respond/summarize/close` 中出现追问时，使用本地合规回复替代或要求一次重写。
3. 研究 NK-GeniOS 是否支持真正的系统变量、隐藏参数或工具参数；若支持，替换当前“将控制上下文拼进 Query”的兼容方式。
4. 将“用户明确结束”“总结后确认”“低信息退出”统一为本地 `close` 事件，并保证幂等。

## 5. P2：建立非诊断性“测评结果”标准

### 原则

报告不能只是“收集到什么”，也不能伪造量表分数或临床诊断。每项测评结果必须有用户证据、状态和适用边界。

### 报告结果维度

1. **信息充分度**：信息充分 / 部分充分 / 信息有限或拒答。
2. **当前困扰画像**：只归纳明确表达的主题、时间线和状态表现。
3. **功能影响判断**：未见明确影响 / 存在一定影响 / 影响较明显 / 未能判断。
4. **安全评估状态**：未披露明确即时风险 / 需进一步确认 / 建议现实支持 / 信息不完整。
5. **建议等级**：继续自我观察 / 建议后续支持 / 建议尽快现实支持 / 需要人工复核。
6. **证据质量**：每个结果注明直接表达、重复证据、用户确认或信息不足，不展示给学生。

### 判定标准

- 不使用从自然语言推导出的总分、疾病名称或人格结论。
- 数值量表只能在用户明确完成经验证量表时出现，保留量表版本、题目来源、计分规则和适用限制。
- 信息不足时报告“未能判断”，不能用默认低风险或低影响填空。
- `SEVERITY_LEVEL` 继续只表示非诊断性安全/分流语义，不能承担所有心理困扰的严重程度。

## 6. P3：自然对话与主题承接

### 目标

让对话从“字段追问”转为“开放表达 -> 承接主题 -> 少量高价值澄清 -> 总结”。

### 改造方向

1. 引入开放邀请模式：回应后允许学生自行展开，不立即索取字段。
2. 维护主题锚点（学业、关系、睡眠、家庭、求助经历等）及其证据，不只维护字段状态。
3. 识别用户的交流偏好：详细表达、简短回应、拒答、纠正、暂停、明确结束。
4. 连续低信息回应优先给出总结与退出空间，不能换同义问题继续问。
5. 建立“追问价值”规则：只有能改变理解、分流或建议的问题才允许询问。

## 8. P5：隐私、同意、留存与访问控制

### 当前风险

会话包含心理文本、身份、风险状态和报告。当前文档中的浏览器持久化说明与实际 `sessionStorage` 快照行为需要重新对齐。

### 改造方向

1. 明确同意文本：收集目的、报告读者、保存期限、撤回方式、紧急例外和联系方式。
2. 制定数据分级、最小化字段、留存/删除期限和导出流程。
3. 将 session snapshot 改为最小必要内容、加密的受控后端保存，或限定短期 sessionStorage 并设置过期清理。
4. 区分学生身份、对话正文、报告、风险复核记录的访问角色与审计日志。
5. 在进入真实学生数据前完成学校伦理、隐私和信息安全审批。

## 9. P6：工作流可靠性与真实状态

### 改造方向

1. 为每个 payload 增加稳定的 idempotency key，避免刷新、重试或 Agent 重复调用写出多行。
2. 将“本地 payload 已生成”“已交给 Agent”“工具执行成功”“Feishu 已确认”建成独立状态，不能合并为“已上传”。
3. 在可用的情况下接收工作流回调或轮询确认，更新真实写入结果。
4. 失败时支持安全重试、失败原因分类和人工补偿，不泄露报告正文。
5. 以 payload hash、workflow run ID、Feishu row ID 串起完整审计链。

## 10. P7：可观测性、质量指标与回归集

### 核心指标

- 总结率、自然收束率、报告生成率、工作流成功率。
- 每会话平均追问数、重复追问率、同一主题重复率。
- `responseMode` 分布与实际 Agent 回复是否合规。
- 安全确认触发率、拒答率、人工复核闭环时长。
- 信息充分度分布、用户主动退出率、恢复失败率。

### 改造方向

1. 记录去标识化事件，不记录多余对话正文。
2. 建立合成对话回归集，覆盖开放表达、低信息、纠正、拒答、结束、高风险和刷新恢复。
3. 对提示词或策略变更运行固定回归集，比较重复追问和收束质量。
4. 将开发者调试面板与生产日志分离，生产环境不暴露任何内部状态。

## 11. P8：学生侧状态页与可控体验

### 原则

第三个状态页可以体现“初步梳理”已发生，但不能展示内部风险标签、字段表、完整报告或诊断性分数。

### 可展示内容

- 对话状态：正在梳理 / 已完成初步梳理 / 已保存待确认。
- 已覆盖主题的非敏感摘要，例如“近期困扰、日常影响、下一步支持”。
- 用户控制：继续补充、纠正本次总结、暂停、结束、重新开始、了解数据处理。
- 仅在适当场景展示现实支持入口。

## 13. 不建议现在做的事项

- 为了“像测评”而直接增加自定义总分、心理疾病标签或未经验证的风险分数。

- 让 Agent 根据记忆自行编写报告或自行决定安全结论。
