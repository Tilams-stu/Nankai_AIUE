## 2. 目标体验与边界

```text
ngrok 临时 HTTPS 链接/二维码
  -> 姓名、学号输入与开始按钮
  -> 自然对话（可自主结束）
  -> 可选：专业补充测评（本地计分）
  -> 静态状态页（不承诺实时评估）
  -> 白噪音空间（播放项目方提供的本地音频）
  -> 对话收束后由本地状态准备报告 -> Agent 工具 -> 飞书测试表
```

本轮收集姓名和学号：姓名仅用于界面称呼，学号作为测试工作流的 `Student_ID`。两者仅保存在当前浏览器会话状态及已有后台工作流范围内，不新增长期身份系统。

## 3. 实施顺序

### P0. 对话与报告闭环稳定性

目标：短回答是对上一问题的正常延续，不能让 Agent 擅自结束；报告只在本地确认的结束事件中准备。

- 收紧 `files/智能体提示词.md`：`clarify` 必须提出一个目标问题；单轮短回答不可被理解为结束；仅 `summarize`、`close` 或用户明确结束语允许收束。
- 新增本地 Agent 回复守卫：当本地 `clarify`/`safety_check` 与 Agent 的明显收束文案冲突时，隐藏纠偏并且每回合最多重试一次。
- 报告触发仅接受本地 `ready_to_close`、`sufficient` 后的确认，或用户明确结束意图；不以 Agent 文字中的通用结束句直接作为成功证据。
- 回归用例包括“情绪压抑 -> 这几天吧”，预期继续澄清功能影响。
- 结束按钮触发的安全确认必须独立于 D1-D10 阶段：学生直接回答“没有”时，本地完成安全状态并提交记录，禁止再把该回答交给 Agent 追问。
- 学生界面不得展示 D1-D10、当前阶段或 Payload 等内部运行状态；这些信息只供本地策略和报告生成使用。

### P1. 小规模试用入口

目标：学生扫码后填写姓名、学号即可开始体验。

涉及文件：

- `index.html`
- `src/app/loginRuntime.js`
- `src/app/pageRuntime.js`
- `src/domain/session.ts`
- `__tests__/mental-prototype.test.js`

实现：

1. 保留“姓名、学号”弹窗，并在前端校验两个字段均已填写。
2. 点击开始后将姓名、学号写入当前会话身份；不再向 Agent 发送姓名/学号介绍消息。
3. 展示非诊断边界和退出入口，不阻塞用户进入聊天。
4. 记录部署说明：启动本地服务后以 `ngrok http 8000` 建立临时 HTTPS 链接；Agent 密钥只留在本机环境变量。

### P2. 专业补充测评界面

目标：将“补充测评”从 Agent 对话转换为可选择、逐题作答、结果可解释的量表界面；复用主聊天页的左视觉区与右工作区布局，量表作答全程本地处理。

首批量表：

- PHQ-9：Kroenke, Spitzer, Williams (2001), DOI `10.1046/j.1525-1497.2001.016009606.x`；9 题，0-27 分。
- GAD-7：Spitzer, Kroenke, Williams, Lowe (2006), DOI `10.1001/archinte.166.10.1092`；7 题，0-21 分。

来源约束：题干和中文译文须在发布前由项目负责人对照授权/官方公开版本逐字确认；实现中保留来源、版本、回顾周期、计分规则和非诊断说明。不得将结果用作诊断、风险结论或自动紧急分流。

涉及文件：

- 新增 `src/domain/supplementalAssessment.ts`
- 新增 `src/services/supplementalAssessmentService.ts`
- 新增 `src/app/supplementalAssessmentRuntime.js`
- `index.html`
- `src/app/pageRuntime.js`
- `src/styles/components.css`
- `__tests__/mental-prototype.test.js`

数据流：

```text
量表选择 -> 本地逐题答案 -> 本地计分/解释 -> AssessmentState.scale_result
  -> 会话快照与后台报告（带量表名称、版本、总分、解释边界）
```

### P3. 白噪音空间可用化

目标：页面在音频暂缺时如实说明，在项目方补充音频后无需改代码即可播放、暂停和调节音量；任一时刻只能播放一个音频。

涉及文件：

- `src/app/soundGridRuntime.js`
- `index.html`
- `public/audio/README.md`（新增）
- `src/styles/components.css`

实现：

1. 当前资源位置为 `public/audio/`，使用 `rain.mp3`、`forest.wav`、`bonfire.mp3`、`wind.mp3`、`night.mp3`。
2. 音频不存在或加载失败时显示“音频资源不可用”，不可伪装成正在播放。
3. 启动新音频前暂停其余音频，所有卡片最多一个处于播放状态。
4. 仅允许卡片自身的播放/暂停和音量控制，不将白噪音描述为治疗或安全处置。

## 4. 可行性自检

| 项目 | 当前证据 | 结论 | 前置条件/限制 |
| --- | --- | --- | --- |
| ngrok 小范围入口 | Python 代理已提供页面与 `/api/chat`，会话可保存姓名和学号身份 | 可实现 | 电脑、代理和隧道必须在测试时持续运行；仅限小范围 |
| 密钥边界 | `NANKAI_API_KEY` 仅由 Python 代理读取 | 可实现 | 不得将密钥填入网页或二维码 |
| 自动报告 | 已有 `agent_internal` payload 与飞书工具字段合同 | 可验证但非自动证明 | 每轮仍需在 NK-GeniOS 日志和飞书测试表核验 |
| 过早收束修复 | 本地已有 `ConversationPolicy`，但 Agent 可忽略 Query 上下文 | 可实现 | 需提示词收紧和本地守卫双层控制 |
| PHQ-9/GAD-7 界面与计分 | 项目有 TypeScript 服务层、会话快照和 `scale_result` 字段 | 可实现 | 中文题干/译本须在公开前做来源和许可复核 |
| 状态页动态化 | 当前使用硬编码图表数据 | 不在本轮实现 | 需先定义学生可见的非诊断数据合同 |
| 白噪音播放 | 已有 HTMLAudioElement 播放、暂停和音量代码 | 条件可实现 | 当前引用的 `focus-sounds-master` 文件不存在，必须改资源路径并由项目方提供音频 |

自检结论：P0-P3 的代码实现可在当前架构内完成。对外组织学生前，必须完成 P0 自动化回归、手工验证一次“本地页面 -> Agent -> 飞书测试表”链路，并确认量表中文版本的来源与使用条件。

## 5. 验收清单

1. 输入“我就是感觉情绪比较压抑”后回答“这几天吧”，不会出现“今天先到这里”。
2. 不说“报告”也能在合法收束后生成测试报告；Agent 的提前结束文案不能单独触发报告。
3. 首次进入要求填写姓名、学号；学号可在飞书测试表中定位。
4. PHQ-9/GAD-7 都能逐题完成、阻止漏题提交、正确累计总分、显示非诊断结果和量表来源。
5. 白噪音严格显示 5 个约定资源；切换卡片后前一个音频暂停，任何时刻最多一个音频播放。
6. `npm run typecheck`、`npm run test` 和 `npm run validate:local` 通过；完成手机端手工试用。
