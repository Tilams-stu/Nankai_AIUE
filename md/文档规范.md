# Markdown 编写与检索规范

## 文件名与目录

文件名使用 `YYYY-MM-DD_主题关键词.md`，例如 `2026-08-01_dialogue-policy.md`。日期用于时间线排序；主题关键词使用一种主语言，避免中英文在文件名中重复表达同一件事。

中文为主要协作语言时，建议文件名使用中文主题，例如 `2026-08-01_对话策略.md`；需要英文检索时，在文档首部补充英文标题和英文标签，而不是另建一份内容相同的文件。

同一件事只保留一个当前版本。被替代的文件标记为“已归档”，并移入 `90-archive/`；不要靠 `final`、`final2`、`最新版` 叠加文件名。

## 文档首部模板

```markdown
---
title_zh: 对话策略
title_en: Dialogue Policy
kind: roadmap
status: active
tags: [dialogue, safety, workflow]
updated: 2026-08-01
---

# 对话策略 / Dialogue Policy

## 结论

## 背景

## 决策与原因

## 相关文件

## 后续行动
```

每份文档先写“结论”，再写过程。中文段落保持中文，英文术语第一次出现时写成“中文（English）”；代码标识、接口名和命令保持英文并用反引号标记。

## 生成要求

向协作助手提出文档请求时，明确给出：文档类型、目标目录、文件名、标题双语格式、标签、结论、关联文件和是否替代旧文档。示例：

```text
在 md/04-development/roadmap/ 创建 2026-08-01_对话策略.md。
使用文档规范中的 front matter；中文正文、英文标题和标签；先写结论；
链接相关测试与进度记录；不要重复已有文档，若替代旧计划请将旧文件移入归档并写明替代关系。
```

## 快速检索

在工作区根目录使用：

```powershell
rg --files md outputs Mental-LLM_JxFdj/docs -g '*.md'
rg -n -g '*.md' '对话|dialogue' md outputs Mental-LLM_JxFdj/docs
rg -n -g '*.md' 'status: active|已归档' md
```

`project-lifecycle` 适合持续执行“计划 -> 开发 -> 验证 -> 进度留档”的项目节奏；对于本工作区，应将其产出的 Markdown 分别归入 `md/04-development/roadmap/`、`progress/` 和 `validation/`。需要强制执行上述命名、双语元数据和归档规则时，可使用 `skill-creator` 创建一个专用的 `markdown-governance` skill，并把本文件作为其约束来源。
