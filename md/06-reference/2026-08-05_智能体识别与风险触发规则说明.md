# 智能体困惑识别与安全风险触发规则说明

## 结论

本项目不是通过一张关键词表判断学生是否存在心理问题。系统采用“大模型语义理解 + 本地确定性规则 + 多轮会话状态”的混合方式：

1. 普通困惑和诉求主要由智能体结合当前消息与历史对话理解。
2. 本地主题提示规则辅助定位持续时间、情绪、睡眠、功能影响和支持系统等评估字段。
3. 安全风险使用独立规则持续召回，并结合否定、主体、时间、引用和历史状态进行确认。
4. 关键词只负责召回线索，不单独完成最终风险判断。
5. 出现新的有效信息或安全状态变化时，系统更新同一会话的结构化报告。

本说明用于答辩、项目交流、代码维护和后续验收。它不是临床诊断标准，也不能替代学校危机干预制度、心理咨询、精神科评估或紧急服务。

## 现场简答版

老师如果问“系统是通过什么关键词识别困惑或诉求的”，可以这样回答：

> 我们把普通困惑识别和安全风险识别分开处理。普通困惑主要由大模型结合上下文进行语义理解，例如学生说“我不知道该怎么办”或“最近和同学相处让我很累”，即使没有命中固定词，也可以识别为需要继续交流的困扰。代码中的关键词主要用于辅助定位评估主题，比如持续时间、睡眠、情绪、学习影响和支持系统。
>
> 安全风险部分有独立的表达模式规则。例如“想消失”“活着没意思”会召回被动风险线索，进入进一步安全确认；“想自杀”“想伤害自己”属于更直接的主动风险线索；“已经割伤”“已经吞药”或“正在伤害自己”进入紧急路径；如果同时出现“今晚”“马上”“已经准备好了”和药物、刀具等信息，风险优先级会进一步提高。
>
> 但是关键词只负责召回，最终还要检查这句话是不是学生本人说的、是否被否定、属于过去还是现在，以及前后文是否一致。比如“我朋友说他不想活了”和“我没有想过伤害自己”不能机械地当作学生本人正在发生的风险。系统最后输出的是非诊断性的工作流分流状态，并把原始证据和状态变化写入报告。

## 1. 两类识别机制

| 识别对象 | 主要机制 | 关键词的作用 | 下一步 |
| --- | --- | --- | --- |
| 普通困惑或诉求 | 大模型语义理解、历史上下文、会话阶段 | 辅助定位评估主题，不直接判定风险 | 自然追问、补充主诉或更新评估字段 |
| 安全风险线索 | 关键词/表达模式、语义分类、量表风险条目、结构化状态和历史峰值并联 | 负责高召回，发现线索后进入安全门控 | 安全澄清、现实支持提示、风险分流和自动报告 |

普通困惑并不存在“命中一个词就开始心理评估”的单一开关。学生的隐含表达、求助意图和上下文关联由智能体理解；本地字段提示只帮助系统避免遗漏对话主题或反复询问同一内容。

## 2. 普通困惑与诉求的主题提示

当前 `conversationPolicyService.ts` 中的字段提示包括以下范围：

| 评估主题 | 当前提示词示例 | 用途 |
| --- | --- | --- |
| 风险披露 | 安全、风险、伤害自己、伤害他人、想活、想死、不想活 | 判断是否需要进入安全确认通道 |
| 功能影响 | 影响、学习、上课、作业、生活、效率 | 了解困扰对学习和生活的影响 |
| 持续时间 | 多久、持续、最近、什么时候、多长时间 | 了解问题发生的时间范围 |
| 情绪状态 | 情绪、心情、焦虑、低落、烦躁、难过、压抑 | 定位情绪相关信息 |
| 睡眠与食欲 | 睡眠、食欲、睡不着、失眠、早醒、吃不下 | 定位身体和生活状态 |
| 支持与求助 | 帮助、求助、支持、心理中心、家人、朋友、老师 | 了解现实支持系统和既往求助 |

这些提示词是主题线索，不是医学症状词典，也不用于判断具体疾病。没有命中提示词的表达，仍然可以由大模型根据语义识别为困惑、求助或继续补充。

## 3. 安全风险关键词与表达范围

下面是当前规则设计与本地实现使用的主要表达类别。列表是可维护的召回范围，不是完整的自然语言可能性集合；含蓄表达、错别字、引用和复杂上下文还需要通过语义理解与安全澄清处理。

| 类别 | 当前表达示例 | 触发含义 | 默认后续 |
| --- | --- | --- | --- |
| 被动死亡或消失愿望 | 想消失、不想醒来、活着没意思、活着没有意义、撑不住了、想躲起来 | 可能存在被动风险或明显绝望 | 进入安全澄清，通常至少记录为 R1 |
| 主动自伤或自杀意念 | 想自杀、想去死、结束生命、结束自己、结束这一切、伤害自己、自残、割腕、轻生、不想活了 | 出现直接主动风险线索 | 优先安全流程，通常进入 R2；临近时升级 |
| 计划或临近时间 | 已经想好、准备好了、计划好了、等某件事结束就、今晚、马上、现在就、这周就、今天就 | 判断是否存在计划和紧迫性 | 结合工具可及性判断 R2 或 R3 |
| 工具或方法可及 | 刀、药、绳子、跳楼、割、吞药、安眠药、工具在身边、已经买了 | 判断风险是否容易实施 | 与主动意念和时间共同评估 |
| 正在发生或已经受伤 | 已经割伤、已经吞了药、吃药过量、正在伤害自己、刚刚自残、已经动手了 | 可能已经进入现实危险 | 直接进入 R3，优先现实医疗支持 |
| 既往风险经历 | 以前自残、之前自杀、曾经割腕、有过自杀尝试 | 记录重要历史风险 | 通常进入 R1，并继续确认当前安全 |
| 伤害他人 | 想伤害别人、想打人、想杀了他、控制不住想伤人 | 可能存在他人安全风险 | 进入 R2/R3 的现实支持路径 |
| 严重精神状态线索 | 幻听、有人命令我、听到声音让我、有人控制我、现实分不清、脑子失控 | 需要进一步专业或医疗评估的线索 | 结合是否有命令性内容和迫近危险判断 R2/R3 |
| 拒答或无法确认 | 不想说、不方便回答、不想回答、不回答、不知道、不清楚、说不准 | 关键安全信息不足 | 进入 RX，不能按“没有风险”处理 |

### 3.1 规则与工作流的典型对应

| 规则 | 典型触发 | 默认工作流 |
| --- | --- | --- |
| CR-001 | 正在伤害、已经受伤、疑似过量服药 | R3，紧急医疗路径 |
| CR-002 | 既往自伤或重要历史风险 | 当前实现通常为 R1，继续确认当前安全 |
| CR-003 | 主动意念同时有计划或工具可及 | 至少 R2；时间迫近时 R3 |
| CR-004 | 被动死亡愿望，或直接风险表达尚无计划信息 | 进入安全澄清并自动记录 |
| CR-005 | 伤害他人的迫近风险 | R2/R3，按正式制度升级 |
| CR-006 | 命令性幻听或现实判断明显受损 | R2/R3，专业或医疗评估路径 |
| CR-007 | 明显躁狂、冲动和危险行为组合线索 | R2，专业评估路径 |
| CR-008 | 量表中的自伤或死亡相关条目阳性 | 暂停量表，进入安全澄清 |
| CR-009 | 风险表达后拒答、退出或信息无法确认 | RX，安全提醒与自动报告 |
| CR-011 | 用户明确否认当前自伤、自杀或伤人想法 | 当前状态可回到 R0，但保留历史证据 |
| CR-012 | 风险主体、引用或规则与模型结果存在冲突 | 采用更保守的路由并记录 |

说明：CR 编号来自设计规则，实际分支以当前 `safetyRuleService.ts` 为准。当前代码中 `CR-002` 主要用于既往风险；设计稿还将近期明确计划或无法保证安全纳入该编号。当前代码对计划或工具可及性主要使用 `CR-003`，再根据时间和行为状态进入 R2 或 R3。后续若统一编号，需要同步本说明、设计稿和自动化测试。

## 4. 触发后的处理顺序

系统不是“匹配关键词后直接下结论”，而是按以下顺序处理：

1. 对输入进行清理并召回可能的表达模式。
2. 判断表达主体是学生本人、他人、引用内容还是未知主体。
3. 判断是否存在否定词，以及内容属于过去、当前、未来还是未知时间。
4. 识别当前行为、当前想法、计划、工具可及性、时间、支持和保持安全能力等维度。
5. 生成内部工作流标签和安全状态，决定继续普通对话、进行安全澄清或提供现实支持提示。
6. 将规则编号、原始证据、时间范围和状态变化写入会话状态。
7. 由报告协调器根据新证据或安全状态变化创建或更新同一会话报告。

因此，“想消失”不是最终结论，而是触发下一步安全确认的线索；“我朋友说他想自杀”也不能直接改写成学生本人的风险；“我没有想过伤害自己”只能说明当前明确否认，不能抹除同一会话此前已经出现的风险证据。

## 5. R0-R3 与 RX 的含义

这些标签只用于系统工作流分流，不是临床风险等级，也不代表疾病诊断。

| 标签 | 系统含义 | 典型情况 |
| --- | --- | --- |
| R0 | 当前对话未披露明确即时风险 | 明确否认当前风险，且没有其他重大线索 |
| R1 | 需要关注 | 被动死亡愿望、既往风险、明显功能受损但当前未见正在发生的危险 |
| R2 | 高度关注 | 主动意念、计划或工具可及、支持不足、无法稳定确认安全或严重精神状态线索 |
| R3 | 紧急 | 正在伤害、已经受伤、疑似过量服药、计划即将实施或无法保证当前安全 |
| RX | 信息不足 | 关键问题拒答、主体或时间不明、信息冲突或系统无法可靠判断 |

报告中应该写“本次对话当前未披露明确即时风险”，不能把 R0 简写成“无风险”。如果后续出现明确安全否认，当前状态可以回到 R0，但 `peakWorkflowLabel` 和风险证据会保留本轮历史峰值。

## 6. 示例

### 示例一：普通困惑

输入：`最近论文压力很大，晚上睡不好。`

- 识别结果：论文压力、睡眠困扰、主诉信息。
- 处理方式：继续自然了解持续时间和功能影响。
- 风险结果：没有因为“压力”或“睡不好”直接判定为安全风险。

### 示例二：被动风险线索

输入：`最近经常觉得想消失。`

- 识别结果：被动风险表达。
- 处理方式：触发安全确认，进一步确认当前想法、计划、工具和现实支持。
- 工作流：通常为 R1，并进入自动报告记录。

### 示例三：主动风险和临近计划

输入：`我想伤害自己，今晚准备吞药，药就在身边。`

- 识别结果：主动意念、临近时间、工具可及。
- 处理方式：中断普通评估，优先连接身边可信任的人、学校心理健康中心或当地紧急服务。
- 工作流：按紧迫程度进入 R2 或 R3。

### 示例四：明确否认和历史峰值

输入顺序：先说“最近经常觉得想消失”，再说“我现在是安全的，没有马上伤害自己的打算”。

- 当前安全状态：可以记录为当前 R0 或已确认当前安全。
- 历史状态：仍保留此前的 R1 风险峰值和原始证据。
- 报告：同时展示当前安全状态与历史风险峰值，不能把整段对话写成“无风险”。

### 7.3 维护要求

1. 新增或修改关键词时，同时更新本说明、规则设计稿和对应自动化测试。
2. 新规则必须说明触发条件、主体和时间处理、默认工作流、报告字段以及误报和漏报测试。
3. 不把关键词扩充当成唯一修复方式。遇到漏报或误报，应先判断问题发生在召回、语义理解、状态合并、响应规划还是报告上传。
4. 任何规则调整后，至少回归测试直接表达、含蓄表达、否定、引用他人、历史表达、风险后改口和拒答退出。
5. R0-R3/RX 仅用于系统分流。对外交流时不要把它们称为临床诊断或正式危机等级。

## 8. 一句话记忆

> 普通困惑靠语义理解，安全风险靠多通道召回；关键词负责发现线索，上下文和确定性规则负责确认分流，报告负责留下可追溯证据。
