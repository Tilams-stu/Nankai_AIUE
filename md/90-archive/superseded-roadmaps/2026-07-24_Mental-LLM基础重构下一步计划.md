## 1. 当前项目现状

`Mental-LLM_JxFdj` 当前更接近一个静态前端原型，主要文件集中在根目录：

- `index.html`：承载主要页面结构、样式和交互逻辑。
- `sdk.js`：前端调用或 SDK 相关逻辑。
- `proxy_server.py`：本地代理服务，用于连接南开 Coze/NK-GeniOS 接口。
- `manifest.json`：PWA 配置。
- `*.glb`：3D 人物或状态模型资源。
- `libs/`：本地第三方库，如 `chart.js`、`marked.min.js`、`model-viewer.min.js`、Font Awesome。

当前主要问题不是功能完全不可用，而是项目结构较集中，页面展示、对话逻辑、接口调用、报告组织和资源管理还没有清晰拆分。后续如果要继续接入 NK-GeniOS 智能体、飞书报告、风险规则和后台复核，会比较难维护和讲清楚。

## 2. 重构目标

本次基础重构只做“工程结构搭建”，不做复杂业务实现。

目标包括：

1. 建立清晰的项目目录，让前端页面、业务逻辑、接口服务、资源和文档分开。
2. 为后续接入 NK-GeniOS 智能体、`report-to-feishu` 工作流和报告生成预留位置。
3. 把前期访谈需求和智能体设计文档转化为代码项目中的模块边界。
4. 保持现有原型可回退，不直接破坏当前 `index.html` 能运行的状态。
5. 为汇报提供一套“我接下来准备怎么改项目”的清晰路线。

## 4. 各目录职责

### 4.1 `public/`

存放不需要参与业务逻辑编译的静态资源。

计划迁移：

- `*.glb` 放入 `public/models/`
- `tubiao.png` 放入 `public/images/`
- `manifest.json` 放入 `public/`

这样可以把“资源文件”和“代码文件”分开，方便汇报时说明项目资源结构。

### 4.2 `src/app/`

存放应用入口和页面装配逻辑。

后续可以把当前 `index.html` 中的大块页面结构逐步拆分出来，但第一阶段不急着重写页面。

### 4.3 `src/components/`

存放界面组件。

后续可拆分为：

- 聊天窗口组件。
- 输入框组件。
- 3D 形象展示组件。
- 状态切换按钮组件。
- 报告预览组件。

第一阶段只规划目录，不强制拆组件。

### 4.4 `src/services/`

存放外部接口调用逻辑。

后续可放：

- `chatService`：负责和 NK-GeniOS / Coze 对话接口交互。
- `reportService`：负责触发报告生成或工作流调用。
- `userService`：负责用户 ID、学号、姓名等基础信息处理。

这样可以避免把 API 请求直接写在页面逻辑里。

### 4.5 `src/workflows/`

存放与工作流相关的配置和说明。

后续可放：

- `reportToFeishu.md`：记录 `report-to-feishu` 的入参。
- `workflowMapping.json`：记录本地字段到工作流字段的映射。

当前已确认 `report-to-feishu` 需要：

```text
input
SEVERITY_LEVEL
Student_ID
time
```

### 4.6 `src/domain/`

存放本项目的核心业务概念。

后续可按智能体设计文档建立：

- 会话状态。
- 主诉字段。
- 功能影响字段。
- 安全筛查状态。
- 报告状态。

这部分不是 UI，也不是接口，而是项目自己的业务模型。

### 4.7 `src/utils/`

存放通用工具函数。

后续可包括：

- 时间格式化。
- 文本清洗。
- 报告字段空值处理。
- Markdown 转义。

### 4.8 `src/styles/`

存放样式文件。

后续可以把 `index.html` 中的大量 `<style>` 逐步拆出，降低单文件复杂度。

### 4.9 `server/`

存放后端或代理服务。

计划迁移：

- `proxy_server.py` 放入 `server/`

它负责本地代理和接口转发，不应和前端页面文件混在一起。

### 4.10 `docs/`

存放工程说明文档，服务于汇报和后续协作。

建议先建立：

- `architecture.md`：说明项目结构。
- `refactor_notes.md`：记录重构原因和步骤。
- `agent_integration.md`：记录 NK-GeniOS 智能体和飞书工作流接入方式。

### 4.11 `tests/`

存放测试和验收材料。

第一阶段可以先放人工测试用例，不一定马上写自动化测试。

建议包括：

- 普通压力对话。
- 睡眠问题对话。
- 功能影响对话。
- 含蓄风险表达。
- 报告生成。
- 飞书工作流调用。

### 4.12 `legacy/`

用于记录旧结构和迁移说明。

第一阶段不建议直接删除旧文件，应先保留可运行版本，再逐步迁移。

## 5. 分阶段执行计划

### 阶段一：只搭目录和文档

目标：不动原有业务逻辑，只建立项目结构。

计划动作：

1. 新建 `public/`、`src/`、`server/`、`docs/`、`tests/`、`legacy/`。
2. 新建 `docs/architecture.md`，说明目录职责。
3. 新建 `docs/agent_integration.md`，记录 NK-GeniOS 和 `report-to-feishu` 的当前接入信息。
4. 新建 `tests/manual_cases.md`，整理人工测试脚本。
5. 暂不迁移 `index.html`、`sdk.js` 和 `.glb` 文件，避免破坏现有原型。

汇报重点：

> 我先完成项目工程结构设计，把原先集中在根目录的静态原型，规划成前端、服务、工作流、业务模型、资源和测试几个区域，为后续接入智能体与飞书报告做准备。

### 阶段二：迁移静态资源和服务文件

目标：把资源和服务从根目录中分离。

计划动作：

1. 将 `.glb` 模型迁移到 `public/models/`。
2. 将 `tubiao.png` 迁移到 `public/images/`。
3. 将 `manifest.json` 迁移到 `public/`，同步检查路径引用。
4. 将 `proxy_server.py` 迁移到 `server/`。
5. 检查 `index.html` 中资源路径是否需要调整。

汇报重点：

> 我把资源文件和代理服务拆出来，降低根目录混乱度，同时保持现有页面可以继续运行。

### 阶段三：拆分前端结构

目标：逐步拆分 `index.html`。

计划动作：

1. 将样式拆到 `src/styles/`。
2. 将聊天相关逻辑拆到 `src/services/` 或 `src/app/`。
3. 将报告展示和 Markdown 处理逻辑拆出。
4. 保留原页面视觉效果，避免一次性大改 UI。

汇报重点：

> 我计划把页面层和逻辑层分离，让后续修改提示词、报告字段或接口时不需要直接改大体量 HTML 文件。

### 阶段四：接入智能体与报告工作流

目标：让本地项目与 NK-GeniOS 原型和飞书报告流转对齐。

计划动作：

1. 在文档中固化 `report-to-feishu` 的入参：
   - `input`
   - `SEVERITY_LEVEL`
   - `Student_ID`
   - `time`
2. 设计本地报告字段与工作流入参的映射。
3. 将“报告状态：待人工复核”作为固定字段。
4. 保持非诊断性表达，不输出临床结论。

汇报重点：

> 本地项目不是单独做一个聊天页面，而是要和 NK-GeniOS 智能体、飞书多维表格报告流转形成闭环。

### 阶段五：补充测试与汇报材料

目标：能证明重构后的项目结构可用。

计划动作：

1. 建立人工测试用例。
2. 测试普通对话、风险表达和报告生成。
3. 截图保存重构前后目录结构。
4. 整理一页汇报材料，说明“为什么要重构”和“重构后支持什么”。

## 9. 潜在风险

1. 当前项目没有标准前端工程配置，不能贸然引入复杂构建工具。
2. `index.html` 体量较大，直接拆分可能引入路径错误。
3. `.glb` 模型文件较大，迁移后需要检查引用路径。
4. 飞书工作流权限仍可能限制真实写入测试。
5. 心理健康相关表达必须保持非诊断性和人工复核边界。
